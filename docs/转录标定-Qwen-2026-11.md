# Qwen3-ASR + CTC 标定记录（Jap_test.mp4 / 2026-11-13）

素材、参照与上一轮 Anime Whisper 标定完全相同：`Jap_test.mp4`（830s，全片耳语、母带
极安静），人工精修版 `Jap_test_perfect.srt`（77 条 / 645 字）作参照。目标不是「一版出
完美字幕」，而是让**一次转写**尽量逼近它。

复现工具都在仓库外 `tune/`：

```bash
python tune/qwen_harness.py run --name x          # 产品路径跑批（含耗时/内存）
python tune/qwen_seg.py --ref Jap_test_perfect.srt # 整段 VAD vs 分窗 VAD
python tune/qwen_probe.py --ref ... --media ...    # 人工时间窗直接送模（隔离识别/分段）
python tune/ctc_align_probe.py                     # CTC 对齐头当通用对齐器的精度
python tune/qwen_replay.py dump|sweep|emit         # 断句参数回放（不跑模型）
```

## 0. 结论：默认参数与三处结构性改动

| 参数 | 旧默认 | 新默认 | 依据 |
| --- | --- | --- | --- |
| `qwen.vad_speech_pad_ms` | 150 | **250** | 耳语片句首常被 VAD 削掉半个词（「悲しそうな顔ね」→「そうな顔ね」）。250 与 Whisper 侧一致，CER 9.83% → 9.15% |
| `qwen.max_segment_s` | 16 | **12** | 16s 窗口会把两三句合并送模，模型开始复读（'おちんぽイッちゃう' 连出两遍）；12s 内容 CER 8.77%（16s 为 9.68%） |
| `qwen.cue_pad_start_s` | 0.12（共用） | **0.20** | 人工版起点比发声早约 0.2s；起点中位偏差 +0.11s → +0.03s |
| `qwen.cue_pad_end_s` | 0.12（共用） | **0.45** | 人工版句尾多停约 0.5s；终点中位偏差 −0.42s → −0.08s |
| `qwen.strip_nonverbal_edges` | 无此参数 | **开** | 见下面第 3 条 |

结构性改动（都在 `core/`）：

1. **分窗 VAD**（`transcribe_array` 改调 `detect_speech_stamps`）。Qwen 一直没跟 Whisper
   侧那次修复，整段一次跑 Silero 的隐状态漂移会漏整条台词：实测**整段一次跑漏 19/77
   条人工台词**（含 461.8s 那段「エッチな音が聞こえてくる」），分窗后 0 条。这是本轮
   最大的一处收益（CER 30.54% → 9.92%）。
2. **句首尾非台词发声剔除**（移植 `strip_edge_nonverbal_ex`）。Qwen 之前完全没有这道
   闸门，笑声会变成字幕：多出 19 条纯「ふふ」/「えへへ」条，且段**中间**的「ふふっ、」
   会被 DP 切到下一条开头——所以在段级剔一次之后，`_cues_from_alignment` 里再按条剔一次。
   顺带补了 `えへへへ` 这类以「え」起头的笑声（原正则要求首字就是呼气字，`え` 会剩下）。
3. **停顿边界从「中性」改成「奖励」**（`_apply_pauses`）。旧行为只把停顿边界的成本清零，
   DP 只有在超过 `max_cue_dur` 时才愿意付 `SEG_BASE_COST` 去切——于是人工版分成两条的
   「今日は…」/「チラチラ見なくていいんだよ」被合成一条。现在停顿按长度给负成本
   （每秒 2.0，封顶 4.0），漏句 16 → 12、合并 7 → 5。
4. 修掉 `_dedupe` 会把条压成**负时长**的 bug（起点被推到前一条终点之后时终点没跟着抬，
   实测写出过 `2.500 → 2.480`）。

## 2. 内存：16 GB 这条建议是错的（已改）

设置页原来给 Qwen 标「建议内存 16 GB」，给 Anime Whisper 标 6 GB。实测（`tune/mem_probe.py`，
45s 切片，加载完成后清零统计峰值）：

| 引擎 | 进程 RSS | MPS 显存 | 合计峰值 | 830s 素材耗时 |
| --- | --- | --- | --- | --- |
| Qwen3-ASR + CTC | 0.75 GB | 4.33 GB | **5.07 GB** | 54s |
| Anime Whisper | 4.60 GB | 2.08 GB | **6.69 GB** | 116s |

也就是说**更快的那一个反而更省内存**：Qwen 的权重按 bf16 直接上 MPS，进程里只有 0.8 GB；
Whisper 的 safetensors 是 fp32，加载时整份留在 RSS（4.6 GB），MPS 上还有一份 fp16。

结论与改动：`min_ram_gb` 改为 **Qwen 8 / Whisper 12**（口径：实测峰值 + 系统与应用余量，
向上取常见配置；原来是照权重大小猜的，两个都错，方向相反）。README / README_EN 同步。

## 3. 还剩什么

1. **内容 CER 9%**：剩余全是耳语下的替换/多字（「せーし」→「精子」、「言っちゃう」→
   「行っちゃう」、句尾「…えへへ」残留）。这是模型能力边界：把人工时间窗直接送模（完全
   正确的分段）内容 CER 就是 9.32%，说明管线已经不再丢字，剩下的都在声学模型上。
2. **切条口径**：漏句 12 条里多数是「参考拆两条、我们合成一条」的配对口径问题（合并 7、
   拆分 7）。要继续收得改断句 DP 的语速/时长模型，不是参数能解决的。
3. **对齐层给 Whisper**：见下一节。

## 4. 通用对齐层（给 Anime Whisper 补逐字时间）

`ctc_aligner_jav_vocalisation_v3.pt` 是 **acoustic-only** 的字符 CTC 头（`input_dim=2048`
= Qwen 音频塔输出，词表 2601 个日语字，`frame_classes=['silence','vocalisation','speech']`），
推理时只要「音频特征 + 目标文本」，文本是外部给的——所以它天生能给**别人的**转写结果打时间。

精度（`tune/ctc_align_probe.py`，用人工文本当天花板，77 条）：

| 指标 | 结果 |
| --- | --- |
| 词表覆盖率 | 未登录字只有标点（`.` 75 次、`?` 19、`、` 8、`。` 1），汉字全覆盖 |
| 起点误差 | 中位 +0.200s / p90 0.360s（去掉系统性提前量后 p90 0.320s） |
| 终点误差 | 中位 −0.597s / p90 0.908s（去掉系统性停留后 p90 0.477s） |
| 对照：Whisper 现状 | 起点 p90 1.35s、终点 p90 1.2s（上一轮 DTW 实测） |

结论：**能用，但达不到 P1-5 定的 ±150ms**。它解决的是「一个 VAD 块里两句话切在哪」，
不是帧级测量。已按可选层落地（`core/align_layer.py` + `whisper.use_ctc_alignment`，默认关）。

### 4.1 内存是怎么排布的（两遍，不叠加）

对齐器要多占一份 Qwen 权重，**不能和 Whisper 同时常驻**。所以实现是两遍：
第一遍 Whisper 只解码、把每段文本排队（`pending`），循环结束先 `engine.release()`
（丢 `_pipe` + `gc.collect()` + `torch.mps.empty_cache()`），再 `LAYER.ensure_loaded()`；
对齐完 `finally: LAYER.unload()`，任何异常/取消都不会把 5GB 留在显存里。

`tune/mem_align_probe.py`（120s 切片，50ms 采样）实测：

| 阶段 | RSS | MPS | 合计 |
| --- | --- | --- | --- |
| Whisper 转写 | 1.83 GB | 2.08 GB | 3.91 GB |
| 对齐器 | 1.92 GB | 4.33 GB | 6.24 GB |
| 全部结束 | 1.88 GB | **0.03 GB** | 1.91 GB |

峰值 6.24 GB，而不是 6.7 + 5.1 = 11.8 GB；结束时 MPS 只剩 0.03 GB（`mps.empty_cache()`
之后确实掉下来了）。代价是**每个任务多一次模型加载**（Whisper 重新热身约 3s）。

300–600s 窗口（17 条人工台词）：CER 5.96% → **5.30%**、起点 p90 0.934s → **0.745s**、
字幕时长中位 3.48s → **2.13s**（人工 2.46s）、起点中位 +0.044s / 终点 −0.200s。
对齐器不可用时会自动回退到原来的按字数分配（实测 3 段全部回退、文本不丢）。
