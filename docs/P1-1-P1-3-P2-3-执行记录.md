## 1. P1-1：Qwen 断句词边界（配评测台）

### 1.1 问题回顾

旧 `_break_costs` 只在“前一个字是助词”时给低分，`_apply_pauses` 又会把“≥0.12s 的字间空隙”一律置为免费切点，导致 DP 只剩时长/字数约束。实测 60–90s 出现：

- `子供の頃、空` / `はもっと、ずっと近かった`（`空|は`）
- `だから、空の匂い` / `を連れてきてくれる雨は好きで、`（`匂い|を`）
- `…雨は好き` / `で、雨の朝は…`（`好き|で`）
- `…連れてきてくれ` / `る雨は好きで、`（`くれ|る`）

### 1.2 新规则（`qwen_ctc._break_costs`）

无分词器前提下，先堵住最确定的四类：

| 规则 | 例子 | 成本 |
| --- | --- | --- |
| 助词前不切（は/が/を/に/で/へ/と/も/の/か/ね/よ/わ/や + から/まで/より） | `空|は`、`匂い|を`、`好き|で` | `BREAK_FORBIDDEN` |
| 两个假名之间默认不切，只有左边是助词/て形才允许 | `くれ|る`；`空は|もっと` 允许 | forbidden / particle |
| 活用尾前不切（る/た/て/だ/な/ば/れ/ら/り/っ/ず/ぬ） | `来|る`、`食べ|る` | forbidden |
| 标点后仍给 0 成本，且**标点本身被对齐时**奖励落在“标点之后” | `、|空` | 0 |

另外加了 `PARTICLE_WORD_EXCEPTIONS`（もっと/こと/これ/それ/でも/だけ/など/みたい/ように/だから/そして…），避免把“以助词字开头的词”误判成助词。

> 这套规则是**启发式**，不是分词器。它能消掉高频劈词，但不能保证 100% 词边界；后续若要继续提升，建议可选接入 `SudachiPy`/`fugashi`（按词性给成本），不要继续堆正则。

### 1.3 评测台

新增 `tools/eval/score_srt.py`（纯标准库，不加载 torch）：

```bash
python tools/eval/score_srt.py \
  --reference 测试用_言叶之庭_中日双语.srt \
  --hypothesis /tmp/qwen_after.srt \
  --from 30 --to 330 \
  --json /tmp/qwen_after.json
```

输出：CER、S/D/I、块均准确率、漏块、最长条、>4.3s、cps、**下一条以助词/活用尾开头的次数**。用法与口径见 [`tools/eval/README.md`](../tools/eval/README.md)。

### 1.4 A/B 结果（30–330s，同一参考、同一模型参数）

| 指标 | 改前 | 改后（A：助词+假名+活用尾） |
| --- | --- | --- |
| CER | 28.16% | **28.16%**（文本逐字相同） |
| S / D / I | 17 / 79 / 2 | 17 / 79 / 2 |
| 候选条数 | 27 | 25 |
| 块均准确率 | 42.3% | 40.1% |
| 漏块 | 14 | 15 |
| 最长条 | 3.76s | 4.48s |
| >4.3s | 0 | 1 |
| 助词开头切分 | 1 | **0** |
| 活用尾开头切分 | 1 | **0** |

解读：

- **识别文本没有变**（CER/S/D/I 完全一致），变化只发生在“在哪里断句”；
- 劈词代理指标从 **2 次降到 0 次**，这是本轮目标；
- 块均准确率下降 2.2pt、最长条 +0.72s，是“减少劈词 → 合并更多短句”的直接代价；参考字幕本身有大量 1–2s 短句，所以按参考块对齐的指标会变差。
- 这不是“全面更好”，而是**可读性优先的取舍**。如果未来更看重逐块对齐，可以在 `partition_cues` 的 `SEG_BASE_COST/OVERRUN_COST` 上做 A/B，而不是重新放开词内切分。

## 2. P1-3：Qwen 编码复用

### 2.1 旧路径

每个分段：

```
_transcribe:  processor → generate (内部 audio_tower 一次)
align:        _encode_audio → _encoder_features (audio_tower 再一次)
```

同一段音频的音频塔前向跑两遍；16s 窗口下这是 Qwen 侧最大的一块可省算力。

### 2.2 新路径

`_transcribe(..., capture_audio=True)`：

1. 用 `model.model.get_audio_features(input_features, mask)` 先算一次；
2. 临时把 `model.model.get_audio_features` 指向同一个 `cached` 输出；
3. `generate` 内部再调用时直接复用，不再跑音频塔；
4. `finally` 恢复方法；
5. 返回 `(text, (projected, times))`；
6. `_align_projected(projected, times, text)` 直接做 CTC 对齐（`align()` 仍保留为独立入口/回退）。

异常兜底：任何一步失败都记录 warning 并回到原来的“二次编码”路径，保证不影响识别。

### 2.3 实测

| 指标 | 旧路径 | 新路径 |
| --- | --- | --- |
| 30–330s 总耗时（含加载） | 19.8s | **16.59s** |
| 产出 SRT | 25 条 / 271 字 | **逐字节相同**（`diff` 无差异） |
| 对齐统计 | 17/18 段 aligned | 17/18 段 aligned |
| 30–630s 总耗时 | 未单独跑旧路径 | 33.73s（52 段，50 aligned） |

约 **16%** 的整体加速；文本与时间轴不变。若后续继续优化，方向是“分段预处理批量化”，而不是再省这一次 projector。

## 3. P2-3：局部转录异步化

### 3.1 旧行为

`transcribe_selection_to_editor` 是同步函数：直接调 `engine.transcribe_file`，没有进度、没有取消；长选区会把该事件占满，UI 只能等。

### 3.2 新行为

改成 generator + worker 线程：

- worker 只做模型调用，`progress_cb` 把进度放进 `queue`；
- generator 线程消费队列，按 10 个输出组件 yield `⏳ 选区识别 [x%]…`；
- 完成后在 generator 线程里做入轨/撤销栈/写草稿；
- 取消令牌沿用 P0-4 的 `JobRegistry`；`stop_btn` 可打断；
- 客户端断开时 generator `finally` 发取消，worker 的 `finally` 释放槽位；
- 事件侧 `show_progress="hidden"`，避免原生追踪器与状态行双源。

实测（30–40s 选区）：

```
yields = 6
[1%] 模型权重就绪…
[2%] 正在提取 16kHz 音频…
[8%] 正在使用 Silero VAD…
[10%] 正在识别第 1/1 段…
[98%] 正在整理字幕…
⚡ 选区已成功转录并直接入轨（已定位至第 1 行）…
```

取消测试：在第一个进度 yield 后 `cancel_for_session`，最终状态为
`⚠️ 选区转录已取消，核对轴保持不变。`，槽位释放。

并发测试：另一个会话占用槽位时，选区转写立即返回「已有任务在运行」，不会启动模型。

UI 实测：

- 60s 片段，Whisper 选区 44.9–60.0s：进度行依次更新，最终入轨 4 条，按钮恢复「⚡ 识别并直接入轨」；
- 同一选区切到 Qwen：异步进度 + 逐字对齐，最终入轨 4 条；日志无“特征复用失败”回退；
- 进度做了单调化（引擎可能先报 2% 提取、再报 1% 加载；generator 取 `max(last, current)`，不会倒退）。

## 5. 已知边界

1. **词边界是启发式**：`もっと`/`こと` 等例外表会漏；没有词性，无法处理所有复合词/专有名词。下一步可选 `SudachiPy` 或 `fugashi`，但会增加安装体积。
2. **减少劈词会让部分短句合并**：块均准确率按参考块计算会下降；这是指标口径与可读性的取舍，已记录，不建议为了该指标重新放开词内切分。
3. **编码复用的副作用**：`get_audio_features` 被临时替换为实例属性；如果未来 transformers 改变 `generate` 的调用方式（不再走 `model.model.get_audio_features`），会自动走 fallback，不会出错但会退回二次编码。升级 transformers 时建议重跑 A/B。
4. **异步选区仍是“单任务”**：与全片转写共享 `JobRegistry` 单槽；不能一边全片转写一边选区识别。这是引擎单例的安全取舍。
5. **模型前向不可中断**：与 P0-4 相同，取消只在解码/分段/对齐段之间生效。
