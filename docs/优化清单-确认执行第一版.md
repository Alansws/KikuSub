## 2. A1｜强制切分点改为能量谷吸附

### 2.1 问题

`transcribe.py:431-443`：

```python
while cursor < end:
    nxt = min(end, cursor + max_samples)   # ← 纯按时间步进，与语音内容无关
```

超过 `max_segment_s` 的语音段被机械等分。日语促音「っ」、长音「ー」、拨音「ん」、无声化母音都只有几十毫秒，刀口落在中间就得到半个音节——模型必然缺字，Whisper 还容易被触发复读。

### 2.2 设计

**只向前找，不向后推。** 搜索窗固定为 `[target - 0.4s, target]`。

理由：单段长度上限是硬约束（Whisper 侧 `MAX_SEGMENT_S_LIMIT = 29.0`，Qwen 侧 16s 送模窗口），若允许向后推，段长会突破上限。而 VAD 段尾本来就是静音，能量谷大概率落在目标点之前，向前找已经够用。

**新增常量**（`transcribe.py` 顶部，与现有 `MAX_SEGMENT_S` 等并列）：

```python
CUT_SNAP_S = 0.40        # 切点搜索窗宽度；0 = 关闭（旧行为）
CUT_SNAP_FRAME_MS = 20   # 能量分析帧长
CUT_MIN_CHUNK_S = 0.50   # 相邻切点最小间隔，防止切点倒退/交叉
```

**函数签名**（向后兼容，`audio=None` 时行为与现状逐字节一致）：

```python
def merge_vad_segments(
    stamps, sample_rate=SAMPLE_RATE, max_segment_s=MAX_SEGMENT_S,
    merge_gap_s=MERGE_GAP_S, min_speech_s=MIN_SPEECH_S,
    speech_pad_s=0.0,          # 现状保留，本次不动
    audio: np.ndarray | None = None,   # 新增
    cut_snap_s: float = CUT_SNAP_S,    # 新增
) -> list[tuple[int, int]]:
```

**切点算法** `_energy_valley_cut(audio, lo, hi, frame) -> int`：

1. `hi - lo < 3 * frame` → 返回 `hi`（窗口太窄，不折腾）。
2. 按 `frame = sr * 20ms` 分帧，算每帧 RMS。
3. 若 `max(rms) / max(min(rms), 1e-6) < 2.0`（起伏 < 6dB）→ 返回 `hi`（连续说话，无显著谷，退化为原切点）。
4. 取 RMS 最小帧，再在该帧内取 `|x|` 最小样本 → 返回样本级索引（精度从 ±10ms 提到 ±1 采样）。

**切分循环改造**：

```python
while cursor < end:
    nxt = min(end, cursor + max_samples)
    if audio is not None and cut_snap_s > 0 and nxt < end:
        lo = max(cursor + int(CUT_MIN_CHUNK_S * sr), nxt - int(cut_snap_s * sr))
        if nxt - lo >= 3 * frame:
            nxt = _energy_valley_cut(audio, lo, nxt, frame)
    if nxt - cursor >= min_samples:
        split.append((cursor, nxt))
    cursor = nxt
```

## 3. A3｜空结果段重试 + 疑似漏句区间清单

### 3.1 问题

`transcribe.py:726-727` 与 `qwen_ctc.py:774-776`：

```python
if not text:
    continue      # ← VAD 判定"这里有人说话"，模型一个字没出，静默丢弃
```

这是最需要人看的地方，却完全不可见。用户只能在成品里"感觉少了一句"，无从定位。

### 3.2 设计

**第一步：增益重试（只对空结果生效）**

```python
RETRY_TARGET_PEAK = 0.85
RETRY_GAIN_RANGE = (0.2, 8.0)   # ≈ -14dB ~ +18dB

def _retry_gain(chunk: np.ndarray) -> np.ndarray:
    peak = float(np.max(np.abs(chunk))) or 0.0
    if peak < 1e-6:
        return chunk
    gain = min(max(RETRY_TARGET_PEAK / peak, RETRY_GAIN_RANGE[0]), RETRY_GAIN_RANGE[1])
    return np.clip(chunk * gain, -1.0, 1.0)
```

返回新数组，不修改原 `audio`（后续段还要用）。

**第二步：可信度安全阀**

重试出的文本不能无条件采信——增益会同时放大噪声。判据：

- `字数 / 段时长 > 15`（日语正常语速 5–7 字/秒，15 已是极限）→ 不可信
- 与上一段文本**完全相同**且长度 > 4 → 不可信（复读）

不可信时**不产字幕**，但仍按漏句记录（`reason = "retry-suspicious"`）。这里不建"幻觉闸门体系"，只是一个作用域极窄的判据，不触碰 A4 的范围。

**第三步：漏句清单**

引擎新增属性 `self.last_missed_spans: list[dict]`，每次 `transcribe_*` 开始时清空。**不改返回值签名**——与现有 `last_interrupted` / `last_stats` 同一模式，避免波及 `app.py` 的 7 处调用点。

```python
self.last_missed_spans.append({
    "start": seg_start_s, "end": seg_end_s,
    "dur": round(seg_end_s - seg_start_s, 2),
    "reason": "empty-after-retry" | "retry-suspicious",
})
```

`seg_start_s / seg_end_s` 已含 `time_offset`，与字幕时间轴同一坐标系。

**流程（两个引擎对称）**

```
text = decode(chunk)
if not text:
    if cancel_event.is_set(): break          # 重试前必查取消
    text = decode(_retry_gain(chunk))
    if text and _suspicious(text, dur, prev_text):
        text, reason = "", "retry-suspicious"
    elif not text:
        reason = "empty-after-retry"
if not text:
    self.last_missed_spans.append(...)
    continue
prev_text = text
```

- [ ] 人工标注的"有人声无字幕"区间数下降

### 4.4 一个必须定死的决策：波形用哪份 wav

**波形固定用 `loudnorm=False` 的原始 16k wav。**

理由：波形是用来"找哪里有声音"的。若用 `dynaudnorm` 版，弱段被抬起、响段被压下，动态被压平，用户会失去对真实响度的判断。

代价：转写档位为 `loudnorm=True`（Qwen 默认）时，首次会生成两份 wav，即 **2 次解码**——但**仅首次**；此后转写、补录、重开核对台全部命中。`loudnorm=False`（Whisper 默认）时只有一份，1 次解码。

相比现状"每次转写都全片解码 + 每次开核对台都全片解码"，长期收益仍然成立。

### 4.5 磁盘与失效

- 体积：16k mono s16 = 32KB/s ≈ **115MB/小时**。
- 上限：默认 4GB（≈35 小时素材），LRU 按 mtime 淘汰。
- 失效：`path + size + mtime_ns` 任一变化即视为不同文件，重新解码。
- 开关：`KIKUSUB_AUDIO_CACHE=0` 完全退回现状。
- 缓存目录在 `outputs/` 下，已被 `.gitignore` 覆盖，无需改忽略规则。

### 9.2 实现期发现并修正的问题

1. **A1 会让段数凭空变多**（计划未预见）。只"向前找"时，若剩余音频刚好是 `max_segment_s` 的整数倍，切点提前 120ms 就把尾段顶过上限，多切出一截 0.12s 碎片（30s+40s 场景 4 段→5 段）。加 `_cut_keeps_segment_count()`：用整数上取整判断"吸附后剩余分段数不变"才接受吸附，段数与覆盖时长严格守恒。
2. **缓存临时文件名必须保留 `.wav`**。`xxx.wav.<pid>.part` 结尾会让 ffmpeg 无法推断容器格式（`Unable to choose an output format`），改为 `xxx.<pid>.part.wav`。
3. **`peaks()` 不能先做 0.25s 预降采样**。原写法在短片段上会把 bins 压到几十个点（10s 片段只剩 39 点，前端波形失真），改为直接在 16k 样本上按 bins 分边取 `max|abs|`，与旧 1kHz 算法同构且与 16k 直读相关 1.0000。
4. **`os.replace` 加固**。少数受限文件系统禁止 rename，`ensure_wav` 在 rename 失败时退回 `copyfile` + 清理，保证缓存仍可用（正常机器不会走到）。

### 9.6 为什么默认参数下全片字幕结果完全不变（实测归因）

现象：同一片源、同样参数，优化前后 SRT 逐字节一致。三项的成因完全不同，其中两项**本来就没有触发条件**。

**触发条件的数学事实**：`merge_vad_segments` 的合并分支带 `duration_if_merged <= max_segment_s` 约束，所以合并块天然不会超过上限；**唯一能产生强制切分的情况，是某一段「单段连续语音」（中间没有 ≥`min_silence_ms` 的静音）本身长于 `max_segment_s`**。A1 只对强制切分点起作用，因此：

| 项目 | 触发条件 | 本片实测 |
|---|---|---|
| A1 | 单段连续语音 > `max_segment_s` | 451 个 VAD 段，中位 1.45s、p99 9.82s、**最长 12.30s** |
| A3 | 某段 VAD 判定有声、但模型输出空文本 | 全片 0 条 `*.missed.json` → 零空段 |
| P1 | 无（只影响耗时与磁盘） | 结果一致是设计目标，不一致才是 bug |

全片 VAD 扫描（`loudnorm=True`，whisper 默认 VAD 参数）结果：

| 配置 | 合并块 | 最长块 | 强制切分 | 吸附 | 累计前移 |
|---|---|---|---|---|---|
| Whisper 默认 `max_segment=20s` | 224 | 19.88s | **0** | 0 | 0.00s |
| Qwen 默认 `max_segment=16s` | 230 | 15.76s | **0** | 0 | 0.00s |
| 假设压到 12s | 238 | 12.30s | 1 | 1 | 0.25s |
| 假设压到 8s | 263 | 12.30s | 8 | 8 | 0.89s |
| 模拟连续独白（每 30s 才停一次） | 91 | 29.6s | 91 | 68 | 13.48s |

结论：**本片最长连续语音 12.30s，两个引擎的默认上限（20s / 16s）都够用，A1 一次都没被调用**——不是"优化没生效"，而是"没有需要切的刀口"。

**对照实验（强制凑齐条件）**：取全片最长连续语音所在的 870–914s，把 `max_segment_s` 压到 8s 制造 1 处强制切分：

- 吸附前 13 条字幕 / 吸附后 13 条字幕，**逐条时间与文本完全一致**；
- 吸附确实执行了（前移 0.10s），但那处机械切点本来就落在「うまいですよ」之后的停顿里，没有切在音节中间，所以文本无可改善。

这说明 A1 的性质是**伤害削减**而非**质量提升**：它只在"机械切点恰好切在音节/促音/长音中间、导致模型缺字或复读"时才改变输出；切点本来就落在停顿里时，吸附前后必然一致。本片的刀口质量本来就不差，因此没有可观测收益。

**A3 同理**：它只在"模型吐空"时介入；全片 451 段全部有输出，重试一次都没发生，自然也不会多出字幕或漏句记录。

**唯一每次运行都成立的收益是 P1**：46 分钟素材首次解码 1.5s、二次进入核对台 1ms；90s 片段转写 10.4s → 4.4s。它不改字幕，改的是等待时间与磁盘复用。

**若要亲眼看到 A1/A3 生效**：
- A1：把「单次送模最长」降到 8–12s，或使用长独白/旁白/歌声/噪声大导致 VAD 找不到停顿的素材，报告里的 `【切分点吸附】` 行会给出实际数字。
- A3：找弱人声、压低音量或 VAD 阈值调得很低的段落，出现 `*.missed.json` 与报告 `【疑似漏句区间】` 即代表生效。（注：此处原先还有一个前置缺陷，导致低阈值下 A3 实际无法触发，见 §10。）

## 10. 追加修复：低阈值下的两处缺陷（2026-10-26）

### 10.1 现象

用 `vad_threshold=0.08` 跑 Qwen3-ASR 全片，`*.missed.json` 一条都没有，报告写「【疑似漏句区间】未发现」；
但清理后的 `*.qwen.clean.srt` 里出现了 93 秒空档。即「字幕明显有空档，漏句清单却说没问题」。

### 10.2 根因一：Silero 退出阈值在 0.15 以下退化为负值

`get_speech_timestamps` 的迟滞默认取 `neg_threshold = threshold - 0.15`：

```python
if neg_threshold is None:
    neg_threshold = threshold - 0.15      # 0.08 - 0.15 = -0.07
if (speech_prob < neg_threshold) and triggered:   # 概率恒 >= 0 → 永不成立
```

语音概率不可能为负，于是**语音段一旦开始就永远结束不了**。实测（同一份 2751.75s 音频，其余参数同默认）：

| 阈值 | VAD 段数 | 语音总时长 | 最长单段 | 送模块数 |
|---|---|---|---|---|
| 0.28（默认） | 448 | 688.4s（25.0%） | 7.7s | 253 |
| 0.16 | 415 | 789.2s | — | 234 |
| **0.08（用户设定）** | **1** | **2721.2s（98.9%）** | **2721.2s** | **171** |

断崖就在 0.15。所以「调低阈值」实际做的不是「更灵敏地捞弱语音」，而是把整片当成一段连续语音，
再由 `max_segment_s=16` 机械切成 171 块（`forced_cuts=170`、`snapped=71`），静音与配乐全部送进模型。

### 10.3 根因二：空判定口径不一致

转录链路的判空是 `if not text`，清理链路的判空是 `is_ellipsis_only`（`ELLIPSIS_ONLY_RE = ^[.…。]+$`）。
而模型对纯静音/配乐**很少返回空串**，返回的是 `…`、`…。`、`♪`。

于是同一段音频出现两种结论：转录链路认为「有内容」→ 不重试、不记漏句、照常写进 SRT；
清理链路认为「空条目」→ 删掉。漏句清单只在转录链路判空时才写入，因此永远是空的。

用户那份 `测试用_言叶之庭.qwen.srt` 是完整证据链：

- 610 条，首条 13.94s、末条 2751.75s，其中 **24 条时长恰为 16.00s**（机械切块指纹）；
- **31 条纯标点条目**：26 条 `…`、5 条 `…。`（另有 3 条 `♪`）；
- 109.3→202.2s 连续 5 条 16s 块，文本全是 `…`；
- `.clean.srt` 删掉这 31 条 → 579 条，空档由此出现，而 `missed.json` 仍为空。

### 10.4 修复

| 位置 | 改动 |
|---|---|
| `transcribe.py` | 新增 `BLANK_TEXT_RE` 与 `_is_blank(text)`：空白/标点/省略号/音符组成即视为无内容 |
| `transcribe.py` | 新增 `VAD_NEG_THRESHOLD_FLOOR = 0.02` 与 `vad_neg_threshold(th)` |
| `transcribe.py`、`qwen_ctc.py` | 两引擎的 VAD 调用显式传 `neg_threshold=vad_neg_threshold(阈值)` |
| `transcribe.py`、`qwen_ctc.py` | 逐段循环的三处 `not text` 判定全部改为 `_is_blank(text)` |

默认参数行为不变：`0.28 → 0.13`、`0.20 → 0.05`，与 Silero 自身推导完全一致，只有 `threshold < 0.17` 才受下限影响。

### 10.6 两处修复的关系

根因一修好后，原本产生 `…` 的 171 个机械块大部分消失（静音不再被送模），
所以本次全片跑完漏句数可能很少——这是**正确结果**，不是功能没生效。
根因二保证剩下真正「VAD 说有人声、模型说不出字」的段（配乐、气声、极弱人声）不会再被静默吞掉。
