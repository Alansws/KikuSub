## 0. 本轮执行的 4 条硬约束（先写在最前面，逐条对照）

1. **E1 是分支红线**：先跑 M0（评测台固化）与 M1（全局阈值 0.45 / 0.35 / 0.30 / 0.25）。
   若某档同时满足「全片 CER 改善 ≥1.5pt」「插入字数 ≤85」「强制切分 ≤3 次」，
   **立即放弃 D1 二次召回**，固化该档参数，把精力投到 M3（D3 短句合并 + D6 超长切分）；
   只有全局降阈值把插入字数顶到 >90 时，才启动 D1。
2. **D1 禁止 `np.where(covered, 0.0, audio)` 全片硬置零**：改为「逐空隙切片 + 边缘淡入淡出 +
   独立 VAD + offset 映射回全片」；捞出的 extra 段若 <1.0s，送 Whisper 前必须补 ≥0.5s 上下文。
3. **D6 禁止脱离文本按时间切半**：无标点时按字符/词级时间戳定位切点；无时间戳时优先在
   助词（は/が/を/に/で/と/て）后 + 发音能量谷找切点，文本与时间对应拆分。
4. **执行纪律**：一次只改一个变量；M2 与 M3 不同轮；每次实验上报
   全片 CER / 去歌 CER / 插入字数（≤90）/ 漏块数 / 耗时。

### 2.3 门禁判定（方案 §7 + 用户第 1 条硬约束）

判据：全片 CER 改善 ≥1.5pt **且** 插入字数 ≤85（硬上限 90）**且** 强制切分 ≤3。

| 阈值 | ΔCER | Δ插入 | 强制切分 | 判定 |
|---|---|---|---|---|
| 0.35 | +1.73pt | −1 | 0 | ✅ 通过 |

| 0.25 | +3.78pt | +25（94 字） | 1 | ❌ 插入超 90 硬约束 |

1. 0.30 已满足「CER ≥1.5pt 改善 + 插入 ≤85 + 强切 ≤3」全部三条，按用户红线**不再写

2. 0.25 / 0.20 的 CER 更低（21.30% / 20.51%），但**插入字数 94 / 103 双双突破 90 硬约束**，

3. 降阈值到 0.20 之所以 CER 还能降，是因为**音乐/雨声段被大量误检后模型开始「猜」**——
   40–45min（主题歌区间）CER 从 44.37% 降到 29.86%（0.30）再到更低，但插入字数同步从
   5 字涨到 8 字、6 字，且 30–35min 段在 0.25 出现 CER 反向恶化（22.36% → 24.84%，插入 +8）。

## 3. M3 D6 单句超长切分（✅ 已完成）

### 3.1 现象与两个来源

方案只写了「`num_parts == 1` 时忽略 `max_cue_dur`」这一个来源。实测发现是**两个**：

1. `num_parts == 1`：整段直接返回（基线 10 条里的大多数）；
2. `num_parts >= 2` 的权重分配：按字数给时长，遇到「一句很长 + 一句很短」仍会超上限——
   0.30 基线的 `#471` / `#472` 是**两条连续 5.00s**（两个 13 字分句平分 10s 段）。

只改第 1 个来源时，全片 >4.3s 只从 12 降到 8（且 8 条全在主题歌区间），正是第 2 个来源。

### 3.2 实现（`transcribe.py`）

| 新增 | 作用 |
|---|---|
| `nearest_text_cut(text, target)` | 三档优先级选切点：**标点后 > 助词后（は が を に で と て へ も の や）> 任意合法位置**，同档取离目标最近；`forbidden_cut_positions` 一律不破 |
| `_split_overlong_single(...)` | 递归拆分：切点从文本选，时间跟着文本走（见下），任一侧 <0.45s 或找不到合法切点就**不切** |
| `_cap_cue_durations(...)` | 统一兜底：两个分支产出的字幕条只要 >`max_cue_dur` 就再过一遍 `_split_overlong_single` |

时间分配的三级优先级（严格按用户第 3 条约束，**没有一处按时间对半硬切**）：

1. **有字级/词级时间戳**（Qwen CTC 路径，`char_times`）→ 直接用该字的结束时间；
2. **有音频**（Whisper 路径）→ 按「切点字符位置 / 总字数」定位，再在 **±0.60s** 内吸附到
   发音能量谷（复用 A1 的 `_energy_valley_cut`，窗口内无显著谷则保留比例位置）；
3. **两者都没有** → 纯按字符比例（仍然不是时间对半）。

### 3.3 实现期修正（两处，都是跑真实数据才发现的）

| # | 问题 | 修法 |
|---|---|---|
| 1 | 能量谷搜索窗 ±0.35s 太窄，真正的停顿常在 0.5s 外 → 退化成按字符比例（断言直接抓出：比例位置 2.50s，静音谷在 3.00s，切点没动） | 放宽到 **±0.60s**，并区分「返回 hi = 没找到谷」与「找到谷」 |
| 2 | 只处理 `num_parts == 1`，多分句分支仍产出 5.00s 两条 | 新增 `_cap_cue_durations` 统一兜底 |

### 3.4 断言（`tools/eval/test_d6.py`，20 项全通过）

覆盖三条红线：**文本守恒**（拆完拼回去一字不差）、**不按时间对半**（能量谷/字级时间戳路径
分别验证切点确实来自文本与声学，而非 dur/2）、**禁则不破**（小假名、长音符、汉字连写、词内
位置永不选）。另含：无合法切点时保持单条不硬切、1.2s 短句不拆、多刀递归后每条 ≤4.2s。

## 4. M3 D3 合并间隔 0.3 → 0.15（❌ 已测，不采纳）

### 4.1 设计

唯一变量 `merge_gap_s` 0.3 → 0.15，其余锁定（阈值 0.30、D6 已在位）。脚本用
`sweep_threshold.py --override merge_gap_s=0.15`，`VAD 不达标块` 的统计也用同一组参数重算。

### 4.2 结果（对比对象 = 0.30 + D6）

| 指标 | 0.30 + D6 | **+ merge_gap 0.15** | Δ |
|---|---|---|---|
| 全片 CER | 22.46% | **22.33%** | −0.13pt |

| 强制切分 | 0 | 0 | — |
| 超长条（>4.3s） | 0 | 0 | — |
| 耗时 | 218s | **255s** | **+37s（+17%）** |

### 4.3 判定：不采纳

方案 E3 的通过线是「**CER 改善 ≥0.5pt 且 耗时增幅 ≤15%**」。实测 −0.13pt / +17%，
**两条都不满足**：

- CER 收益 0.13pt 落在单次 A/B 的噪声带内（历史对照实验里同类差异在 0.7pt 量级）；
- 段数 484→505、耗时 +37s 是确定成本，换来的只有插入字数 −5 这一项小改善。

方案对 D3 的预期是「CER −0.5~−1.5pt」，前提假设是「短句被并进长 chunk 后模型丢掉尾巴」。
实测没出现这个量级的收益，原因是 **0.30 阈值下短句本身已经能被单独检出**（VAD 不达标块
从 82 降到 65），被并掉的那部分短句已经不在主要损失里了。这与 M1 的结论是同一件事的两面：
本轮真正的收益来自召回，不来自合并粒度。

**保持 `merge_gap_s = 0.3`。**
