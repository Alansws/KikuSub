# 设置页重构方案（待确认，未改代码）

> 2026-11-15 · 只做前端 UI 与信息架构，**不改任何后端接口**。
> 本文是动手前的确认稿：页签划分 / 线框 / 令牌新增 / 组件清单 / 验证计划。

## 0. 一句话结论

把现在「一条竖排里 6 个分区、5 种白框、路径与 repo ID 直接摊在卡片正面」的设置页，改成
**4 个页签 + 1 个本机总览看板 + 2×2 Bento 引擎网格 + macOS Inset 分组列表**：
引擎页承担「本地模型中心」的厚度，其余三页做减法，三套主题共用一套新令牌。

## 2. 信息架构：4 个页签

侧栏 ⌘1–⌘8 主导航**完全不动**，设置页内部做第二层页签（持久化在
`localStorage['kikusub.settingsTab']`，用 ⌘, 回来时停在上次那一页）。

| # | 页签 | 收进来的旧分区 | 主角（一眼看到什么） | 主动作 |
| --- | --- | --- | --- | --- |
| 1 | **引擎与模型** | 引擎与模型（4 引擎 + OmniVoice） | 本机总览看板：MPS / 模型占用条 | 运行首次配置 / 下载模型 |
| 2 | **外观与朗读** | 工作流与外观（主题、明暗）+ TTS 对照 | 三张主题缩略图 | 点缩略图切主题 |
| 3 | **AI 与技能** | AI 优化 + Agent 技能 | AI 服务地址与 Key 状态 | 保存 / 测试连接 |
| 4 | **环境与诊断** | 运行环境 + 日志与诊断 | MPS / Python / ffmpeg 三张指标卡 | 复制精简诊断 |

理由（为什么不拆成 5 页）：

- 「TTS 对照」单独一页太空（只有 2 个偏好 + 1 条路径），并入「外观与朗读」后，
  这一页的主题是「这台机器上你看到/听到什么」。
- 「Agent 技能」与「AI 优化」是同一个心智模型（把字幕交给外部模型），但一个走 API、
  一个走 agent 写文件；合成「AI 与技能」一页，正好用两条 Inset 分组讲清区别。
- 「路径管理」和「日志诊断」都属于「机器状态」，合并后能共用顶部指标卡，路径才有"折叠"的余地。
- 引擎页需要 1000px 宽做 Bento；其余三页内容窄，同宽会让 Inset 列表显得空。**页宽统一 1000px**，
  用内容密度（Bento 两列 vs 单列列表）而不是改页宽来区分，避免切页时页面横向跳动。

## 4. 视觉与交互规则（新东西都靠令牌，不写颜色/px）

1. **分段导航**：`--seg-track` 轨道 + `--seg-thumb` 白色胶囊 + 1px `--seg-thumb-ring`。
   选中态靠「胶囊 + 极淡描边」，不靠纯阴影（白胶囊压浅灰轨道只有 1.05:1，旧主题已踩过）。
   深色下胶囊改 `#262c36`，避免白块刺眼。高度 30px、圆角 `--rad-tab`、图标 14px。
   键盘：←/→ 在 tablist 内移动（`role=tablist` + `aria-selected`），焦点环用 `--accent-ring`。
2. **总览看板**：`--hero-bg` 是一层 `linear-gradient` 强调色薄雾压在 `--raise` 上（三套主题各一个色），
   边框 `--hero-border`。大数字用新字阶 `--fs-hero`（27px）。分段占用条高度 9px，
   段间 2px 间隙用 `--meter-gap`（等于卡片底色，形成 macOS 存储条的"断开"感）。
   未安装的一类用 `--meter-track` + 斜纹（`repeating-linear-gradient`）表达"这部分还没占"。
3. **Bento 卡片**：默认 `--bento-bg` + `--bento-border`；**在用**态 = `--bento-border-on` +
   `--bento-bg-on` + `--bento-shadow-on`（光晕用 `--bento-glow`，不用大投影堆叠）。
   被停用的卡只降强调（`opacity .88`），不做灰化，避免读成"不可用"。
4. **能力指标条**：一行 = `标签(52) | 轨道(1fr) | 数值(96)`。速度/时间轴用 `--meter-a`（越高越好），
   内存用 `--meter-muted`（越短越省），颜色差异本身就在提示"哪个方向是好"。
5. **渐进披露**：卡正面只留「名字 + 一句定位 + 三条指标 + 状态/体积 + 详情」。
   路径、HF repo、必需文件、备注都进 `详情`；`详情` 展开用 `--separator` 虚线分隔 + `--fill` 底。
6. **下载进度**：贴在卡片内部、与 footer 同高的一块（`--meter-track` 轨道 + `--accent` 填充），
   完成变 `--success`、失败变 `--danger`。**footer 高度恒定 44px**，进度出现时卡片不跳高。
7. **Inset 分组**：`--inset-bg` + `--inset-line` 行分隔，行高 46px，左文右控；
   次要说明压在标题下一行（12px `--text-3`），不做成两列表格。
8. **主题缩略图**：用「迷你窗口」而不是色块：侧栏条 + 内容条 + 一句真实日文字幕，
   字幕用该主题的 `--font-cue`（明朝墨才显示明朝），配色取注册表里的 `preview`。
   选中 = `--bento-border-on` + 右下角 `--accent` 对勾。
9. **布局断点**（跟随应用现有的 CSS 视口判定，不看窗口像素）：
   ≥1120 内容宽 = Bento 两列；1120–860 = 单列（页签右侧提示与看板脚注隐藏，避免折行）；
   ≤900（应用紧凑模式，侧栏收成 56px）= 指标卡也单列。任何断点下都不许出现横向滚动。
10. **减法**：路径 3 条明面 + 8 条折叠；日志摘要 1 行 + 动作行 + 120 行原文默认收起
   （`<details>`，不新增弹层）；AI 的 200/120/5 三个数字参数收进「高级参数」，折叠标题右侧
   用 12px 灰字把当前值串出来（`每块 200 · 翻译 120 · 上下文 5`），不打开也知道现在是多少。

## 7. 能力指标的数据口径（这条决定方案诚实不诚实）

界面上的「速度 / 时间轴 / 内存」不是拍脑袋的 0.8 分，全部取仓库里已有的实测数字：

| 引擎 | 速度（实测） | 时间轴（实测） | 内存 | 出处 |
| --- | --- | --- | --- | --- |
| Anime Whisper | 830s 素材 116s → **7.2× 实时** | 起点 p90 1.35s | 峰值 6.7 GB | [Qwen 标定 §2](../../转录标定-Qwen-2026-11.md) |
| Qwen3-ASR + CTC | 830s 素材 54s → **15.4× 实时** | 起点 p90 0.36s | 峰值 5.1 GB | 同上 |
| SenseVoice-Small | 345s 素材 7–8s → **46× 实时** | 边界 F1 0.678（±0.4s） | 权重 0.23 GB | [中文标定 §1](../../转录标定-中文-2026-11.md) |
| FireRedASR2-AED | 345s 素材 102–104s → **3.3× 实时** | 边界 F1 0.545 | 权重 1.4 GB | 同上 |

展示规则：

- 速度用**正向倍数**（`15.4× 实时`，越大越快），不用反直觉的 RTF（`0.07×`）；
  条长 `sqrt(倍数 / 同语种最快)`，跨数量级（46× vs 3.3×）时慢的那个仍然看得见；
- 其余数值原样显示（`±1.35s` / `F1 0.68` / `6.7 GB 权重`），**不伪造小数**；
- 条长 = 同一语种对内归一（日语两枚互比、中文两枚互比），所以两张卡永远可比；
- 分区标题旁写清口径："指标为本机实测，内存条越短越省"、"中文侧内存按权重口径"；
- 每张卡的「详情 → 备注」里放一句实测结论 + 指向标定文档；
- 数据集中放在 `lib/settings/engineMetrics.ts`，**不散在模板里**；换素材重测只改一处。

4. `desktop(view)`：`SettingsView.svelte` 收成骨架，删除旧样式块，下调 `style-baseline.json`。
5. `docs`：`sprints/2026-11-settings-redesign/落地记录.md` + 截图入 `docs/images/shots/`。

每一步都能独立构建、独立截图对照，出问题只回滚一步。
