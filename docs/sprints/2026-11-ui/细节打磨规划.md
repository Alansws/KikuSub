## 3. 任务详情

### T1 · 200% 缩放与窄宽降级（P0）

**现象（实测）**：`KIKUSUB_ZOOM=2`、1360 窗口 → CSS 视口 680×419；侧栏 236 + 检查器 348 占掉 584，内容区 96；视频被压成 44×25，表格列全部被挤没；工具栏标题直接不可见。

**目标**：在 680×419（1360 窗口的 200%）与 540×340（1080 窗口的 200%）下，不出现横向滚动条、不出现 0 宽内容、核对台主路径（看画面、播、选句、改字、暂存/导出、切页）仍可用。**≥900px 的桌面宽屏布局必须与现在逐像素一致。**

**改法（推荐，按这个做）**：

1. **断点只加媒体查询，不改桌面结构**：
   - `@media (max-width: 900px)`：进入紧凑模式。
   - `@media (max-width: 700px)`：进一步降级。
   - 页面缩放会让 CSS 视口变小，所以媒体查询自动生效，不需要 JS 监听缩放。
2. **侧栏（`Sidebar.svelte` + `app.css`）**：≤900px 时宽度 236 → **56px 图标轨**：隐藏 `.brand-name/.brand-sub/.sb-count`、隐藏分组标签、`.sb-item` 只留 16px 图标并居中、`padding` 收到 8px。图标仍有 title 与 aria-label。≤700px 保持 56（不再隐藏，避免新增汉堡菜单）。
3. **检查器（`Inspector.svelte` + `App.svelte`）**：≤900px 时从「占位列」改为**右侧抽屉**：`position: absolute; right: 0; top: 0; bottom: 0; width: min(348px, 92vw); z-index: 20; box-shadow; ` 加一个半透明 backdrop；`app.inspectorOpen` 仍由工具栏按钮控制，Esc 关闭。进入紧凑模式时**自动关一次**（`matchMedia('(max-width: 900px)')` 的 change 里把 `app.inspectorOpen = false`），回到宽屏时恢复 true；不要永久改写用户的桌面偏好（用会话内的临时值或记录“上一次宽屏值”）。
4. **工具栏（`Toolbar.svelte`）**：≤900px 隐藏 `.tb-sub`；≤760px 隐藏引擎分段（`Whisper/Qwen3`，引擎在设置里仍可切）；「AI 优化 / 导出」只留图标（`aria-label` + `title`），「⋯」保留。
5. **核对台（`ReviewView.svelte`）**：≤900px stage padding 26 → 16，视频 `width: min(640px, 100%)` 自然缩；≤700px 表格隐藏「结束 / 时长」两列（grid 改 `30px 78px minmax(0,1fr) 36px`），表头同步。检查器抽屉打开时表格在背后，不参与布局。
6. **其他页**：逐个在 680×419 下过一遍。设置页是 720 单栏居中、提示词/导出 1120、导入/转写双栏——如果 680 下出现横向溢出，把页面根容器改成 `width: 100%; max-width: …; padding: clamp(16px, 4vw, 48px)`，不要动 900px 以上的值。
7. **验收**（必须截图）：
   - `KIKUSUB_ZOOM=2` + 1360 窗口：核对台（检查器关/开各一张）、导入、转写、导出、设置、提示词、AI、报告，亮色即可；暗色补核对台一张。
   - `KIKUSUB_ZOOM=2` + 1080 窗口：核对台一张（540×340）。
   - 1360/1440 宽屏回归：与 `/.oil-ui/p1-review/shots/review-*.png` 对比，布局不得变化。
   - 断言：`document.documentElement.scrollWidth === innerWidth`，`.player` 宽 ≥ 300（680 下）、`.rows` 高 ≥ 90。

**风险 / 注意**：
- 抽屉不要用 `position: fixed` 盖住窗口标题栏（红绿灯区域）；用 `.workspace` 内的 absolute。
- 抽屉打开时 `QaPanel` 的浮标仍可能压在右下角，检查层级（抽屉 z 20，QaPanel 目前更高，必要时把 QaPanel 的浮标在紧凑模式缩小）。
- 200% 下视频解码/波形不受影响（canvas 按 CSS 尺寸重算，DPR 4 时位图更大，注意 `canvas.width` 上限；如果卡，把 dpr 限制到 2）。
- 不要在 ≤900 的媒体查询里改字号（12px 下限不变）。

### T3 · 表格 / 时间线细节（P1）

- **当前句完整**：1360 下已能完整显示（≤1400 媒体查询 + 文本右内边距 6）。任何列宽调整后都要重测这一条：选中第 2 行，文本不得出现省略号。

- **双语行**：`app.track === 'both'` 时行 60；长译文必须两行内省略，不能把行撑破；检查 `.line.sub` 的 12px 与实际行高。
- **字幕轨道**：`LANE_H=17` + `EDGE=6` 在 200% 下变成 34/12 设备像素，可点；100% 下如果觉得窄，可把 LANE_H 提到 19–20，同时同步 `laneTopOf()`、绘制与命中，别只改 CSS。改前先量 `wave-resize` 与 lane 的重叠。

### T4 · 动效手感（P1）

先盘点现状（本轮新增）：页面 280ms 淡入 + 4px 上移；toast 180ms；⋯ 菜单 140ms；历史面板 160ms；选区条 140ms；hover 120ms；抽屉（T1 新增）。检查：
- **首屏**：`viewIn` 不要在冷启动第一帧也播（会像“页面晚了一拍”）；加一个 `mounted` 标记，首屏不播，切页才播。
- **切页**：280ms 是否偏慢；桌面工具建议 200–240ms。用两条录屏（`--record`）对比，选一个，不要反复横跳。
- **抽屉**：T1 的检查器抽屉用 180ms `transform: translateX`，不要动 width（会触发布局）；backdrop 120ms 淡入。
- **跟随滚动**：`revealRow` 现在是直接写 `scrollTop`。播放中跳句时保持瞬时（不要 smooth），暂停时点行可以 120ms smooth；只改一处，别把播放中的跟手弄丢。
- **reduced-motion**：确认页面/抽屉/toast/菜单全部被 `@media (prefers-reduced-motion: reduce)` 关掉。
- 验收：三条录屏或 `--frames` 序列图（切页、选择、抽屉），记录实际时长与是否有跳帧；不动画高度/宽度。
