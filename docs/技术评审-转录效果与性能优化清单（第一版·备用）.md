## 1. 结论速览

**三条真正的地基**（决定成品字幕质量的地方，按影响力排序）：

1. **分段层**——"VAD 合并 + 最长时长硬切"。它决定了模型**听到什么**，比模型本身更早地决定了上限。
2. **时间轴层**——CTC 逐字强制对齐 + 日语断句动态规划。它决定了**字幕怎么切、什么时候出现**。
3. **后处理层**——缝合、去重、重叠裁剪、空行清理。它决定了**成品能不能直接用**。

界面交互、波形手感、撤销栈这些是"用起来顺"，不是"做得对"。本文不涉及。

**最值得动手的 6 件事（P0，均为低风险、不改模型、不动默认参数语义）：**

| # | 事项 | 一句话理由 |
|---|---|---|
| A1 | 硬切点改为能量谷吸附 | 现在是在音节中间随机下刀，吞字就发生在这一步 |
| A3 | 空结果段自动重试 | 现在 `if not text: continue` 把"模型没出字"静默吞掉，漏句无法被发现 |
| A4 | 幻觉/复读闸门 + 统一后处理层 | 现在只有一条正则兜底，音乐段幻觉会直接进成品 |
| A5 | 断句 DP 加可读性约束（最短时长 / 字每秒） | 现在 21 个字塞进 0.6 秒也是合法解 |
| A6 | 对齐降级可观测 | 现在用户无法知道哪几句是 40ms 精度、哪几句是比例近似 |
| P1 | 一次解码供全链路复用 | 现在同一个文件至少被 ffmpeg 全片解码两遍 |

**明确不该动的 7 件事**见第 7 节。

## 2. 核心卖点的技术底座

把"卖点"还原成机制，才能判断哪条是真壁垒、哪条只是包装。

### 2.1 音频层：一切精度的物理起点

| 卖点 | 实际机制 | 含金量 |
|---|---|---|
| 全本地推理 | 权重懒加载到 `models/`，`HF_ENDPOINT` 走镜像 + `snapshot_download` 断点续传；设备自动 `MPS → CUDA → CPU`，`PYTORCH_ENABLE_MPS_FALLBACK=1` 兜住不支持的算子 | **工程壁垒**。同类工具大多卡在"装不上、下不动" |
| 时间区间转写 + 原片绝对时间轴 | `-ss` 输入侧快进（关键帧级）+ `-t` 限长，再叠加 `time_offset` 还原绝对时间 | 中。逻辑简单，但"切片后时间还对得上原片"是很多工具做错的地方 |
| 弱人声增强 | `dynaudnorm=f=150:g=15:m=10.0:r=0.9:b=1` 单声道下混 + 峰值归一化（`max_amp < 0.4` 时拉到 0.85） | 中。**是双刃剑**，见 A/B4 |
| 波形与监看 | 服务端 1kHz 解码出峰值数组（2400–8000 bins）+ 前端 Canvas（DPR 适配、`requestAnimationFrame` 播放线、`fastSeek` 松手才跳） | 中。技术不难，但"长片拖拽不卡"是真实体验分水岭 |
| 兼容性兜底 | 480p 代理压制三级回退：VideoToolbox 硬解硬编 → 软解硬编 → libx264 ultrafast | 中。解决 MKV/HEVC 浏览器黑屏这个真实痛点 |

### 2.2 分段层：最被低估的地基

`Silero VAD → 按 gap 合并 → 按最长时长硬切`（`transcribe.py:402-443`）。

这条链决定了送进模型的音频**边界在哪**。Whisper 与 Qwen 都吃"一段干净、边界落在停顿处"的输入；边界一旦落在音节中间，模型输出必然缺字或复读——这是模型能力之外的系统性损耗，也是本文认为**性价比最高的优化位置**。

现状的两个具体缺陷：
- **硬切与内容无关**：`cursor + max_samples` 机械步进，切点纯按时间算（`transcribe.py:438-442`）。
- **`speech_pad_s` 是死参数**：`merge_vad_segments` 签名收了它，函数体从未使用（`transcribe.py:408`），容易让人误以为"留白已参与合并判断"。

### 2.3 时间轴层：项目的真差异化

**引擎 B（Qwen + CTC）** 的技术含量集中在这里：

- **单次前向同时拿文本与发声帧**：`audio_tower` → `multi_modal_projector` → 自研 `CtcAlignmentHead`（LayerNorm → Linear 降维 → ConvTranspose 2× 上采样 → 4 层膨胀残差卷积 → 分类头）→ `torchaudio.functional.forced_align`。
- **时间分辨率 40ms 是硬事实**：encoder 帧 80ms × upsample 2。这是 head 训练时定死的，不是实现选择（见 N2）。
- **帧—时间映射**按 100 mel 块分段计算 `_conv_length`，处理了变长 padding，不是简单的 `i * 0.04`。这段代码是整个仓库里最容易写错、也写得最对的一段。

**断句层**才是真正难复制的资产（`qwen_ctc.py:260-447`）：

- 切点代价：句末标点 −6（鼓励切）、逗号 0、句中 35（强烈不鼓励）、助词后 1.2、汉字→假名 2.5、**禁则 1000**（小假名、长音符、ASCII 词内、片假名连写、汉字连写、敬语前缀+汉字、"ま"+"す/せ/し"、35 个禁切词）。
- 停顿证据：CTC blank 连段 ≥ `min_pause_s` 的位置，把代价降到 0（`_apply_pauses`）。**这是"声学证据覆盖语言学先验"的设计，方向是对的。**
- 动态规划：段数基础代价 0.1 + 超软上限 1.5/秒 + 超硬上限 3.5/秒 + 超字数 1.2/字，DP 求全局最优。

这套东西的价值在于：**它把"ASR 文本"变成了"可播字幕"**。模型再准，断句断在「ありがと／う」上也是废的。这是本项目相对"套个 Whisper 出 SRT"的工具最实质的差距。

**引擎 A（Whisper）** 的时间轴是明确的近似：段边界来自 VAD，段内按 `3.0 + 字数` 加权比例分配（`transcribe.py:496-528`）。README 已经诚实标注了这一点——这也是 B1 想解决的问题。

### 2.4 后处理层：成品可用性的最后一公里

- `_heal_broken_cues`：按"下一句以小假名/长音开头""汉字接汉字""片假名接片假名"等 9 条规则缝合被劈开的词（`qwen_ctc.py:838-890`）。
- `_dedupe`：排序 + 重叠裁剪（前句尾部截到后句起点）+ 再缝合一遍。
- 纯标点/纯省略号清理：`*.clean.srt`。

方向正确，但**缝合规则偏激进**（见 3.1 问题 6）。

### 2.5 工程可靠性层

可取消（`threading.Event` + 队列轮询 + `GeneratorExit` 时兜底置位）、增量抢救（`*.part_cancelled.srt`）、自动草稿 + 断点、预设原子写入（`presets.py`）、全参数留痕报告。

这一层不产生"效果"，但决定"敢不敢拿它处理两小时的片子"。**它比大多数单点优化更值钱，改动时要格外小心不要破坏**（N7）。

## 4. 转录效果的剩余优化空间

模型固定，但"模型听到什么、听到多长、什么时候被切、切完怎么拼"全在代码里。以下按杠杆排序。

### A1｜硬切点改为能量谷吸附 ★最高优先

- **现状**：超过 `max_segment_s` 的语音段按固定步长机械切断（`transcribe.py:438-442`）。
- **为什么影响效果**：日语里「っ」促音、长音「ー」、拨音「ん」、无声化母音都只有几十毫秒。刀口落在中间，模型拿到半个音节，输出缺字；Whisper 还容易因此触发复读。
- **改法**：在目标切点 ±0.4s 内，用 10–20ms 帧算 RMS（纯 numpy，无需模型），取局部能量最低点作为实际切点；不越过相邻 VAD 段边界。能量平坦（连续说话）时退化为原切点。
- **成本**：低（约 40 行）。**收益**：切点处吞字率下降。**风险**：低。
- **验证**：统计切点落在能量 10% 分位的比例；对 20 个含长句片段做 A/B 看首尾字错误率。

### A2｜解码上下文外扩（Qwen 先行）

- **现状**：送模音频 = VAD 段本身。VAD 的 `speech_pad_ms` 是固定值，而句首辅音（k/s/t/p）能量低，VAD 常在辅音**之后**才触发。
- **后果**：「そんな」→「んな」，句首假名系统性丢失。
- **改法**：送模时前后各多给 150–250ms（clamp 到相邻段中点）；因为 Qwen 有 CTC 逐字时间，可以按"首字起点"精确裁掉外扩部分，不会带进多余文本。
- **注意**：Whisper 路径**不要**先做这个——没有字级时间，外扩会直接带进幻觉文本。等 B1/B2 落地后再考虑。
- **成本**：中。**收益**：句首字准确率。**风险**：中（裁剪逻辑要严格）。

### A3｜空结果段自动重试 ★

- **现状**：`if not text: continue`（`transcribe.py:726`、`qwen_ctc.py:775`）。
- **为什么重要**：VAD 判定"这里有人说话"但模型一个字没出——这恰恰是最需要人看的地方，现在被静默吞掉了。用户只会在成品里"感觉少了一句"，无从定位。
- **改法**：对空结果段做一次重试：增益 +6~9dB（若原始峰值接近 1.0 则改为 −6dB 防削波）→ 再解一次；仍为空则写入"疑似漏句区间"清单，进报告并在核对台标出来。
- **成本**：低。**收益**：直接提升召回，且把静默失败变成可操作信息。**风险**：低（只对空结果生效，不影响正常段）。

### A4｜幻觉闸门 + 统一后处理层 ⛔ 已排除

> **状态：已排除。** 实测两个模型均经过动漫/影视语料微调，未出现「ご視聴ありがとうございました」类音乐段幻听，该项不成立，不执行。

- **现状**：只有 `REPEATED_CHUNK_RE`（6 次以上重复单元折叠）和纯标点清理。纯音乐段 Whisper 会输出「ご視聴ありがとうございました」「おやすみなさい」；也会把上一句整段复读。
- **改法**：在"引擎输出 → 分句"之间插一层 `postprocess.py`：
  - **段级**：字/秒 > 12（日语正常语速约 5–7 字/秒）判可疑；`speech_s/seg_s` 低但文本长判可疑。
  - **文本级**：常见幻觉句正则表（可配置，不写死在代码里）；与上一句完全或近似重复判可疑。
  - **字符级**：标点归一（重复「。。」、「、、」→ 单）、长音符/波浪线统一、去模型自带说话人标签。
  - **关键设计**：**可疑项标记而不是静默删除**，进报告让用户决定。误杀「はい」连说两次这种合法重复的代价，比放过一条幻觉更大。
- **成本**：低-中。**收益**：成品可信度。**风险**：中（误杀）。

### A5｜断句 DP 加可读性约束 ★

- **现状**：`partition_cues` 只有上限约束（软 3.8s / 目标 4.3s / 硬 5.2s / 21 字），**没有下限**。21 个字塞进 0.6 秒在代价函数里是合法解；`_cues_from_alignment` 事后把短句拉到 0.35s，仍然远远不够读。
- **改法**：加两项代价（改 5 行）：
  - `dur < max(0.8, n_chars / 9)` 时按缺口线性罚（9 字/秒是"能读"的下限）。
  - `cps = n_chars / dur > 6.5` 时罚（6.5 字/秒是"读得舒服"的上限）。
  - 借时间优先向**后一句**借（现有 `ceiling` 逻辑已经支持），而不是硬拉。
- **顺带**：把 Qwen 的禁则表抽成公共函数，给 Whisper 路径的 `split_text_into_cues` 做超长兜底（解决问题 4）——**同一份语言学资产服务两条引擎**，这是低成本高一致性收益。
- **成本**：低。**收益**：观感明显提升，**一个字文本都不改**。**风险**：低。

### A6｜对齐降级可观测 ★

- **现状**：`aligned/total` 只出现在进度提示里，转瞬即逝；报告里没有。
- **改法**：报告增加"逐字对齐成功率 / 降级段数 / 降级区间清单"；核对台表格对降级行加标记（可选）。
- **成本**：极低。**收益**：把"40ms 精度"从宣传语变成可验证的产品承诺，也让 A/B 有据可依。

### B1｜Whisper 文本 + Qwen CTC 时间轴（混合模式）　⏸ 待定

> **状态：待定，暂不执行。** 保留技术评估，后续如需要再启动；在此之前不引入双模型驻留。

- **核心洞察**：CTC 对齐头与 ASR 模型**解耦**——它只需要 `(audio, text)`。所以完全可以用 Whisper 的文本 + Qwen 的 encoder/CTC 做强制对齐。
- **价值**：直接消掉 README 里"Whisper 句内时间是近似值"这条硬限制。两个引擎从"文本质量 ↔ 时间精度"二选一，变成"文本质量 + 时间精度"可叠加。这是本清单里**唯一能改变产品定位**的一条。
- **代价**：需同时驻留 Qwen（约 4GB）+ 每段多一次 encoder 前向；速度介于两者之间。CTC vocab 覆盖不到的汉字会变 unk，其时间靠 `_fill_unaligned` 插值（已有逻辑）。
- **建议**：做成可选开关「精确时间轴（复用 CTC 头）」，默认关，文档写清代价。不要在没跑通之前替换默认路径。

### B2｜Whisper 原生词级时间戳（B1 的轻量替代）

- `return_timestamps="word"`，transformers 用 cross-attention + DTW 出词级时间，**不需要第二个模型**。
- 前提：`generation_config` 里要有 `alignment_heads`（large-v3 微调通常保留），缺失时 try/except 回退到现状。
- 精度不如 CTC（DTW 受注意力峰值平滑影响，实测常在 ±80–150ms），但远好于"按字数比例分"。
- 速度约慢 20–40%（DTW 开销）。**若 B1 成立，B2 降级为"不想多占 4GB 内存"时的折中。**

### B3｜两行折行 + 禁则处理

- **现状**：单行输出，靠 `max_cue_chars` 控宽。成品在播放器里会被自动换行，位置不可控。
- **改法**：输出层加 `wrap_two_lines(text, 13~16 字/行)`，行首禁「、。，）」等，行尾禁「（「『」等，优先在助词/标点后断。
- **成本**：低。**收益**：成品可直接用。**风险**：极低（可选开关）。

### B4｜响度处理从"开关"升级为"模式"

- **现状**：布尔开关 → `dynaudnorm`。它是逐帧动态增益：静音处抬 BGM、响处压人声，对 ASR 是双刃剑；且滤波器状态依赖上下文，**切片与全片结果不一致**。
- **改法**：三档：`关闭` / `峰值归一化`（复用 `load_wav_mono` 现有逻辑）/ `EBU R128 loudnorm`（两遍，I=-16 LUFS, TP=-1.5）；`dynaudnorm` 保留为"强动态场景"档。
- **注意**：**不要改默认值**。默认值一改，所有历史预设的语义就变了（N4）。只加档位，并在报告里标注当前档位。

### B5｜环绕声源中置优先

- 5.1/7.1 影视源对白主要在中置声道，`-ac 1` 走 ffmpeg 默认下混会把 L/R 的 BGM 与效果声一起混进来，降低对白 SNR。
- **改法**：`ffprobe` 读 `channel_layout`；≥5.1 时用 `pan=mono|c0=0.7*FC+0.15*FL+0.15*FR`（或直接取 FC）。仅对环绕源生效。
- **成本**：低。**收益**：电影场景对白清晰度，VAD 与 ASR 同时受益。**风险**：低。

### B6｜对齐失败二分重试

- **现状**：`too-few-frames` / `no-spans` 直接整段降级为比例分配。
- **改法**：失败时按能量最低点一分为二，各自对齐；仍失败再降级。
- **成本**：中。**收益**：降低降级率，尤其快语速段落。

### C 组（需实测，别先做）

| # | 事项 | 说明 |
|---|---|---|
| C1 | Whisper 质量模式 | `num_beams=3` + `compression_ratio_threshold` 温度回退。时间 2–3×，只作"离线精修"开关 |
| C2 | `initial_prompt` 注入日语句读风格 | 成本极低，但收益高度不确定；Whisper 路径的断句**完全依赖标点正则**，所以标点质量直接决定分句质量。值得单独 A/B |
| C3 | `afftdn` 频谱降噪 | 只在噪声源明确的素材上开，默认关。伪影会伤 ASR，不能默认启用 |

## 5. 性能优化清单

只列"有真实重复劳动或可测浪费"的项。按收益/成本排序。

| # | 项目 | 现状依据 | 改法 | 收益量级 | 风险 |
|---|---|---|---|---|---|
| P1 | **一次解码供全链路复用** | `app.py:1007` 波形单独全片解成 1kHz；`transcribe.py:325` 转写又全片解成 16k | 落盘 `audio_cache/{stem}_{size}_{mtime}.wav`（16k mono s16）；波形峰值从该 wav 算（每 250ms 取 max abs），转写直接读它 | 2 小时片源省 1 次全片解码（约 10–40s）；补录/重转**零解码** | 低。需加 LRU（16k mono s16 ≈ 115MB/小时） |
| P2 | **消除 Qwen 每段二次 encoder** | `qwen_ctc.py:774` `generate` 内部走一次 `audio_tower`；`788` `align` 再走一次 | 先算 `projected`，再用它同时喂 CTC 与生成（`inputs_embeds` 路径）；退一步至少复用 mel 特征 | encoder 约占单段 10–20%，可省一半 → 总时长 5–10% | **中**。依赖 `AutoModelForMultimodalLM` 内部 API，**先用 profiler 量，别盲改** |
| P3 | **分段批处理** | `for` 循环逐段 `generate` | 按长度分桶（±1s），同桶 pad 到等长，batch 4–8；CTC 同样批量 | GPU 上 1.5–2.5×；MPS 收益小 | 中。padding 可能影响边界行为，显存上升 |
| P4 | **`max_new_tokens` 自适应** | `qwen_ctc.py:486` 固定 440 | `min(440, int(dur * 12) + 32)`（16s 窗口日语上限约 8 字/秒） | 偶发复读时最坏延迟从 440 token 降到约 200 | 极低 |
| P5 | **双引擎互斥驻留** | `ENGINE` 与 `QWEN` 均为模块级单例，加载后不释放，同驻约 7GB | 切引擎前对非目标引擎 `del` + `empty_cache()`；提供"常驻"选项 | 内存峰值减半，避免 OOM 退 CPU | 低（代价是来回切重载数秒） |
| P6 | **峰值缓存落盘 + 上限** | `app.py:816` 无上限 dict，不落盘 | `outputs/.cache/peaks/{key}.npz`；内存侧 LRU(8) | 重启后核对台秒开；长会话不涨内存 | 极低 |
| P7 | **`_break_costs` 禁切点预计算** | `qwen_ctc.py:311-324` 对每个候选切点遍历约 35 个词、每个词 `find` 扫描 → O(n·W·n) | 一次扫描把禁切区间标进布尔数组，切点 O(1) 查表 | 单段从 10⁵–10⁶ 次字符串操作降到 O(n·W)；段多时可见 | 极低（纯等价重构） |
| P8 | **分段级断点续跑** | 中断只保 cues，重跑从 VAD 重来 | 把 segments 与每段结果写 `{stem}.segments.json`，从下一段继续；key 用参数哈希失效 | 长片重跑 O(n) → O(剩余段) | 低-中（缓存失效要处理干净） |

**不建议做的性能项**：
- 给 Silero VAD 上 GPU——CPU 上已足够快，搬上 GPU 的传输开销大于收益。
- 把 `forced_align` 挪到 GPU——`log_probs` 需要转 CPU，段内 T 只有几百帧，GPU kernel 启动开销更大（`qwen_ctc.py:626` 现在就是 CPU，是对的）。
- 多进程并行转写——模型权重 4GB，进程间不共享，内存直接翻倍。

## 6. 怎么证明优化真的有效（先建度量，再改代码）

现在没有任何量化基线，这是比任何单点优化都更该先补的地基。否则所有"感觉好一点"都无法证伪。

**建 4 类各 3–5 分钟的标注片段**：
1. 动画日常对话（干净、快语速、大量小假名）
2. 剧场版 BGM 重（音乐与对白交叠）
3. 耳语 / 低声（当前 VAD 阈值最难的一档）
4. 多人重叠说话

**六个指标**：

| 指标 | 定义 | 关注点 |
|---|---|---|
| CER | 字错率（需人工参考文本） | 文本准确度 |
| 漏句数 | VAD 有人声但无对应字幕的区间数 | A3 的直接指标 |
| 边界误差 | `|cue.start − 标注 start|` 的中位数 / P90 | A1/A2/B1 的直接指标 |
| 对齐降级率 | `1 − aligned/total` | A6/B6 的直接指标 |
| 幻觉条数 | 人工判定为无中生有的条目 | A4 的直接指标 |
| RTF | 处理耗时 / 音频时长 | 所有 P 组 |

**纪律**：一次只改一个变量，同音频同参数；结果写进项目已有的任务报告（扩两个字段即可）。建议加 `bench/run_bench.py` 输出 JSON 对比表——**这比清单里任何一条优化都更值得先做**。

## 7. 不要动（Negative List）

这七条都是"看起来能优化、实际不该碰"的：

1. **不要换 VAD**。Silero 是当前"精度 / 体积 / CPU 可跑"的最优解；pyannote 需要额外权重与 GPU，与"全本地、轻量"的定位直接冲突。
2. **不要试图提高 CTC 时间分辨率**。40ms = encoder 80ms ÷ upsample 2，是 head 训练时定死的；改 head 需要重训，不是代码问题。
3. **不要为"更好看"重写前端波形与状态机**。DPR 适配、rAF 播放线、`fastSeek` 松手才跳、撤销栈、断点续跑都已到位；重写只会引入回归。
4. **不要在没有标注集的情况下改默认参数**。VAD 阈值、`cue_pad`、`max_chars` 都是用户可调项，改默认会破坏 6 套历史预设的语义。要改就加档位、加标注，不改默认。
5. **不要引入第二个 ASR 模型做"二次投票"**。成本翻倍、收益不确定，且直接违背"模型固定"的前提。
6. **不要默认打开 `dynaudnorm`**。Whisper 路径默认关是经过考虑的；B4 是加档位，不是改默认。
7. **不要为了性能牺牲可取消性与增量保存**。这是本项目相对 CLI 工具的核心差异；任何批处理/并行改造都必须保留 `cancel_event` 在每个段边界可中断。

## 9. 一句话总结

这个项目的地基不在模型，而在**"分段决定模型听到什么、断句决定字幕怎么出现"**这两层——它们已经做得比大多数同类工具扎实（尤其是 CTC 对齐 + 日语断句 DP 这套组合）。

剩余空间也不在模型：**A1（切点）、A3（漏句可见）、A4（幻觉闸门）、A5（可读性约束）** 四条都是"不改模型、不改默认、低风险"的系统性修复，加起来能明显抬升成品可用性；**B1（Whisper 文本 + CTC 时间轴）** 是唯一能改变产品定位的一条，但要先有 bench 才敢上。
