### 0.1 时间轴铁律（D-1 仍然成立）

双源润色会把**带时间戳的 A、B 都放进提示词**，让模型按时间对齐参考；但：

- 模型输出永远只有 `{i, text}`；
- 应用时 `start/end` 一律取自核对台当前 A 的 cue；
- 单源载荷的形状不变（没有时间码），旧提案直接可用。

「时间轴不变」仍是**结构保证**，不是提示词承诺。

## 1. 用户工作流

### 流程 A：单引擎，人工把稿子做干净（现有主线，不变）

1. 导入 → 转写（引擎 A）→ 进核对台。
2. 清质检队列、逐条试听、框选局部「转写选区」修正。
3. 某一句拿不准时，点「🎧 用另一引擎再听一遍」——只对当前句实时复核。
4. 原文满意后 → 润色（单源）→ 翻译 → 导出。

### 流程 B：双引擎对照 + 双源润色

1. 先按流程 A 用引擎 A 转出一版（进核对台）。
2. 在转写页换引擎 B（或同引擎换参数）再整片转一次；结果去向选「放进双引擎复核」。
3. B 的稿进入第二列，核对台零改动；转写页给出「已放进双引擎复核」与直达按钮。
4. 「双引擎复核」页两列只读，像 git diff：
   - `=` 一致；`~` 文本不同（逐字高亮）；`+` 仅 B 有；`−` 仅 A 有。
   - 顶部统计、只看差异、点击第 1 列回核对台定位。
   - 兜底：丢弃第二版 / 整列用 B 覆盖核对台（一次历史，⌘Z 可退）。
5. 润色页切「双源」：A | B（可折叠）| AI 终稿 三栏。三种采用粒度都走
   `apply_polish()`：逐条采纳、应用全部差异句 / 仅已采纳差异句、整列全部应用。
6. 原文定稿 → 翻译（只吃 A）→ 导出。

> 翻译永远不参与双引擎比较；第二版也不进 50 步统一历史。

- `core/dual_review.py`：时间重叠 + 文本相似度**纯 1:1 逐条配对**（不做 1→2 / 2→1
  合并，绝不多条并一行）；`=` / `~` / `+` / `−` 归类与 `char_ops` 逐字 diff。
  每次实时计算，不持久化下标；统计恒满足 `A=配对+仅A`、`B=配对+仅B`。
- `tests/test_dual_review.py` 覆盖：一句拆两句（保留额外行）、整体偏移 0.2s、空列表 / 单边为空、漏句不漂移、`A=配对+仅A` / `B=配对+仅B` 不变量。
- `views/DualView.svelte`：两列只读、统计栏、只看差异、回跳核对台、丢弃、整列覆盖二次确认。
- 侧栏徽标只显示 `stats.badge`（`~` 行数）。

### S4：双源润色协议、三栏对照、长片智能分段 ✅

- `core/ai_proposal.py`：`build_proposal(texts_b=…)` 写 `digest_b` / `count_b`；
  `validate_proposal(..., texts_b)` 校验 A + B，任一不符 409，字幕零改动；
  单源提案没有 `digest_b` 时仍可应用（向后兼容）。
- `core/ai_polish.py`：双源分块；每块 A 用全局序号 + SRT 时间戳，B 只取时间窗
  `[t0-2s, t1+2s]` 上下文；输出仍是 `{i, text}`。
- `lib/aiSegments.ts`：长片智能切分（目标 150 条、±20 条容差、找 A/B 静音间隙最大的边界）；
  `desktop/test/segments.test.mjs` 有单测。
- `routes_ai.py`：`/api/ai/prompt` 支持 `mode/from_index/to_index`；`/api/ai/from-srt`
  支持分段回填，序号全局 / 相对都能用，条数不符给出
  「本段期望第 k–m 条（共 X 条），实际解析到 Y 条」。
- `PolishView.svelte`：单源 / 双源、三栏（B 可折叠）、逐条采纳、全部差异、整列应用、
  长片分段条与逐段复制 / 粘贴状态跟踪。**双源不要求 A/B 条数一致**：B 只作带时间戳的
  参考上下文，AI 终稿仍严格按 A 的序号与时间轴输出；B 多几句/少几句都不影响生成、复制和回填。
  条数不同时页头用**中性灰次要文案**提示（正常现象，不用警告色）。
  **2026-11-14 修复**：粘贴解析成功后立刻把提案写成标准文件（`POST /api/ai/proposal`），
  应用时再把内联 `proposal` 一起交给 `/api/ai/apply`；这样切到翻译页再回来、或重开页面
  都不会因为「磁盘上没有提案文件」而被清空。手动粘贴没有逐条理由，`note` 一律为空，
  页面的「理由」列自动隐藏，来源只在页头用一个「外部粘贴」徽标表达。

## 3. 接口与数据（现行）

### 3.1 第二版

```text
Session.alt_review: AltReview | None      # 内存
AltReview = {engine, cues, source, params, created_at, media_path}
边车: {output_dir}/{stem}.{media_cache_key}.autosave_draft.alt.json
```

- `media_cache_key` = 绝对路径 + 文件大小 + mtime_ns 的 sha1 前 16 位。
- 切媒体：`sync_alt_review()` 先清内存，再按新媒体身份尝试恢复。
- 删除：内存 + 边车一起删；整列覆盖成功后默认清空第二版。

### 3.2 复核统计

```json
{"total": 12, "same": 9, "diff": 3, "only_a": 0, "only_b": 0,
 "a_count": 12, "b_count": 12, "badge": 3}
```

`badge` 只等于 `diff`；`+` / `−` 单独展示。

### 3.3 提示词分类

| 分类 | 变量 | 默认模板 |
| --- | --- | --- |
| `polish_single` | `{{SRT}}`、`{{RANGE_HINT}}` | 单源润色（默认） |
| `polish_dual` | `{{SRT_A}}`、`{{SRT_B}}`、`{{RANGE_HINT}}` | 双源润色（默认） |
| `translate` | `{{SRT}}`、`{{LANG}}` | 原有模板 / 成熟汉化组 |

库文件字段：`selected`（翻译）、`selected_polish_single`、`selected_polish_dual`。

## 4. 明确不做

- 不做复核页的逐句 `+`/`−` 局部合并：断句与时间戳不一致时合并 Bug 风险远大于收益。
- 不为双引擎重写核对台历史：采用仍然走 `apply_polish()` / `replace_review()`，一次历史。
- 翻译不做双版本（D-3/D-4 不变）。
- 不在本轮重写 `desktop/resources/skill/`；只保证单源提案契约不变。
- 不做 MLX 迁移、模型候选评测、ForcedAligner spike（仍在日语引擎路线文档排期）。
