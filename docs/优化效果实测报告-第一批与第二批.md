## 0. 一句话结论

**两批优化在这份素材上都没有带来可测量的识别质量提升，但也没有带来伤害。**
真正值钱的是三项**不改变识别文本**的改动：P1 解码缓存（1736ms→0.02ms）、P6 波形落盘（2474ms→101ms）、A5 禁切点（全片 145 处接缝 0 处断词）。
A1/P4 在本片连触发条件都不存在；A3 触发了 2 次但收益为 0；A6 只是把账目对齐；P7 收益绝对值可忽略。

| 项 | 设计目标 | 本片是否触发 | 对结果的影响（实测） | 判定 |
|---|---|---|---|---|
| **A1** 切点能量谷吸附 | 刀口不落在音节中间 | **0 次**（最长语音块 11.68s < 上限 12s） | 强制场景下 CER 23.12%→23.21%（−0.09pt，方向不一致） | ⚪ 无效也无害 |
| **A3** 空段重试 + 漏句清单 | 漏句可见可补 | 2 次（均为静音误判） | 重试救回 **0/10** 空段；漏句清单 **0/2 真阳性** | ⚪ 机制对，本片零收益 |
| **P1** 一次解码全链路复用 | 免重复解码 | 每次都触发 | 冷 1736ms → 热 **0.02ms**；波形 2474ms → **101ms** | 🟢 **有效（性能）** |
| **A5** 禁切点 | 不把词劈开 | 3~6 处接缝 | 断词 1→0（5 分钟 A/B）、全片 145 接缝 **0 断词**；CER 不变 | 🟢 **有效（可读性）** |
| **A6** 对齐四桶统计 | 降级可观测 | 3 区间 7 段 | 桶守恒成立；但「插值率定位识别错」**不成立** | 🟡 只值观测 |
| **P4** 撞上限分类 | 不白烧重跑 | **0 次**（无段吃满上限） | 未触发 | ⚪ 未验证 |
| **P6** 波形落盘 | 重启免重算 | 每次 | 186ms → **42ms**（内存 0.117ms） | 🟢 有效（性能） |
| **P7** 禁切表预计算 | 去 O(n²) | 每次 | 24ms → 0.6ms（42×），绝对值 <1ms | ⚪ 收益可忽略 |

另外有两个**比优化本身更重要**的发现：

1. **交付字幕不可复现**：同代码同参数连跑两次，逐条完全一致（474 条）；但交付的那份是 417 条，差的 57 条集中在 15–20min 与 42–44min。→ §6
2. **真正的损失不在任何一项优化的射程内**：全片 1264 个错字里，**677 字（54%）是 VAD 根本没把这段送去识别**，268 字是识别错，只有 0 字属于「VAD 送了但模型吐空」——也就是 A3 唯一能看见的那一类。→ §7

## 1. 测试方法

### 1.1 为什么不能「跑一遍看结果」

字幕质量必须对着**外部基准**量，否则只能凭感觉。这里用官方双语字幕做参考，先把它转成可比的日语基准：

- 官方字幕是「双条目同时间轴」写法（日语行、中文行各一条，起止完全相同）→ 按 `(start,end)` 归并，取含假名的那条；
- 剔除无假名条目（画面文字「万葉集」「靴職人？」等，ASR 本来就不该出）、剔除制作组信息；
- 得到 **482 个台词块 / 5315 字**，覆盖 00:38–45:36。

### 1.2 指标

| 指标 | 定义 | 为什么用它 |
|---|---|---|
| **CER** | 参考全文 vs 产物全文的字符级编辑距离 / 参考字数 | 全局唯一可比数字；容忍 1→N 切分 |
| **块均准确率** | 每个参考块内逐字对齐后完全命中的比例 | 比 CER 更能看出「整句丢了」 |
| **漏块** | 准确率 <35% 且 ≥3 字的块数 | 漏句计数 |
| **插入/删除字数** | 编辑操作按时间聚类后的字数 | 分别对应「幻觉」与「漏句」 |
| **cps / 条长** | 每条字幕的字/秒、时长分布 | A5 的唯一可量化出口 |
| **禁切接缝** | 相邻两条字幕的接缝是否落在 `forbidden_cut_positions` 的禁切位 | A5 是否真的没把词劈开 |

### 1.3 环境与参数

Python 3.13.12 / torch 2.14.1 / transformers 5.20.2 / 设备 MPS。
Whisper 侧严格复刻你报告里的参数：`threshold=0.45, min_speech=120ms, min_silence=150ms, speech_pad=200ms, merge_gap=0.3s, max_segment=12s, min_speech_s=0.08, cue_pad=0.02s, ngram=5, penalty=1.15, loudnorm=关`。

### 1.4 A/B 的构造方式

每一项都**只改一个变量**：

- A1：同一段音频，`cut_snap_s=0` vs `0.4`，其余完全相同；并额外加一组「等长但不等能量」的对照（5.6s 机械切），用来区分「吸附的功劳」和「切点换个位置的运气」。
- A3：同一批低能量段，原音频 vs `_retry_gain()` 增益后各解一次。
- A5：同一批段文本，`forbidden_cut_positions` 正常 vs 强制返回全 0。
- P1/P6/P7：同一文件冷/热两路计时 + 逐样本比对。
- A6/P4：真实模型跑 3 个区间，直接读 `last_align_stats`。

## 3. 第一批（A1 / A3 / P1 + §10）

### 3.1 A1 切点能量谷吸附 —— 本片一次没触发

**触发审计**（同一份音频、同一组 VAD 参数）：

```
524 个 VAD 段 → 合并成 296 块，最长块 11.68s，上限 12s
→ 强制切分 0 次，吸附 0 次
→ merge_vad_segments(..., cut_snap_s=0) 与 cut_snap_s=0.4 的返回值逐元素完全相同
```

原因在数学上就注定了：`merge_vad_segments` 的合并分支带 `duration_if_merged <= max_segment_s` 约束，合并块天然不超上限；**只有单段连续语音本身长于上限才会强制切分**。本片最长 11.68s，刀口根本不存在。

**强制造出刀口后的 A/B**（取语音最密的 3 个 60.4s 窗口，模拟「VAD 没找到停顿」，按 6s 强切 10~11 刀）：

| 窗口 | 切点处相对能量（off→on） | CER off | CER on | Δ | 文本变化块 |
|---|---|---|---|---|---|
| 330s | 2.96 → **2.10** | 18.85% | 23.36% | **+4.51pt（变差）** | 10/11 |
| 975s | 0.88 → **0.79** | 11.15% | 10.79% | −0.36pt | 11/11 |
| 2415s（歌曲段） | 0.98 → **0.93** | 39.35% | 35.48% | −3.87pt（变好） | 10/11 |
| **平均** | — | **23.12%** | **23.21%** | **+0.09pt** | — |

**关键对照**：把切点改成「等长 5.6s、但不看能量」，三窗口 CER = 15.57% / 15.83% / 36.13%，平均 **22.51%**——比吸附版（23.21%）还略好。

结论：**吸附确实把切点能量压低了 4%~29%，但这不转化为 CER 收益**。三种切法的平均 CER 挤在 22.5%~23.2% 的 0.7pt 带内，窗口间波动却高达 ±4pt。也就是说，本片 CER 的起伏由「刀口落在哪个词上」的运气决定，A1 只是换了个位置，并没有系统性避开伤害。

> 机制层面也能解释：Whisper 遇到半截词会在两侧各自复读一次（实测 `…探さ` + `…さないで`），换到能量谷后照样会在新刀口复读（`…ほっとき` + `…っけよ`）。A1 移动了问题，没有消灭问题。

**判定：无效也无害。** 保留不会更差（`cut_snap_s=0` 与 0.4 在无强制切分时逐元素相等），但也别指望它提分。

### 3.2 A3 空段重试 + 漏句清单 —— 机制正确，本片零收益

**重试救回率**：取全片 24 个「低能量但有语音」的 VAD 段（RMS 最低的一批，0.3–3.0s），原音频与增益后各解一次：

| 项目 | 数量 |
|---|---|
| 首轮判空（含 `…` / `♪` 这类占位符） | 10 / 24 |
| 增益重试后由空变有字 | **0** |
| 其中文本基本正确 | **0** |

**你报告里那 2 条漏句**：

| 区间 | 时长 | RMS | 全片 VAD 段响度分位 | 参考字幕此处 |
|---|---|---|---|---|
| 14:43.416–14:44.072 | 0.66s | 0.0079 | 第 5 百分位 | **无台词** |
| 28:05.464–28:05.992 | 0.53s | 0.0087 | 第 6 百分位 | **无台词** |

两条都是 VAD 把雨声/环境音判成了语音，模型返回 `…`（`_is_blank` 判空 → 重试 → 仍空 → 记漏句）。**精确率 0/2**——清单是空的信号，反而会消耗你对告警的信任。

**覆盖率**：重跑产物里有 **75 个参考块完全没出字幕**，A3 的漏句清单覆盖其中 **0 个**。因为 A3 只能看见「VAD 送了、模型吐空」，而本片这种段是 **0 段**（见 §7）。

**判定：逻辑与落盘都对（三处输出、`time_offset` 叠加、取消检查均实测正常），但在本片上是 0 收益 + 2 条噪声告警。**

### 3.3 P1 一次解码全链路复用 —— 唯一每次运行都成立的收益

| 路径 | 耗时 |
|---|---|
| 冷启动（删缓存后 ffmpeg 全片解码 46 分钟音轨） | **1736 ms** |
| 缓存命中 | **0.02 ms**（≈ 8.7 万倍） |
| 关闭缓存（`KIKUSUB_AUDIO_CACHE=0`，旧行为，每次转写都要付） | **1262 ms** |
| 核对台波形：旧 ffmpeg 直读 1kHz | 2474 ms |
| 核对台波形：新缓存 16k | **101 ms** |

**正确性**：缓存 wav 与现场重新解码**逐样本完全一致**（44,028,000 samples，md5 相同）→ 缓存只加速、不改结果。

一处需要如实说明的副作用：波形数据源从 1kHz 直读换成了 16k 缓存，两条包络的相关系数是 **0.873**（不是文档里写的 1.0000）。差异来自 1kHz 降采样对峰值的平滑，视觉上等价（都是 2 位小数归一化），但**不是逐字节相同**。

### 3.4 §10 两处追加修复

| 修复 | 在本片是否起作用 |
|---|---|
| VAD 退出阈值下限 `vad_neg_threshold` | **不起作用**。阈值 0.45 → 退出阈值 0.30，与 Silero 默认推导完全一致；只有阈值 <0.17 时才受下限影响。这是给低阈值场景兜底的 |
| 空判定统一 `_is_blank` | **起作用**。上面 2 条漏句记录就是 `…` 被判空后走重试的证据 |

遗留：交付字幕里仍有 2 条纯标点条目（`、` 和 `!?`）。它们不是「整段吐空」，而是一段文本被 `split_text_into_cues` 切出来的碎片（例如 `…いいわよ` 切成 `…` + `いいわよ`），`_is_blank` 管不到这一层。影响很小（2 条），但说明「纯标点」有两个来源，清理链路只堵了一个。

## 4. 第二批（A5 / A6 / P4 / P6 / P7）

### 4.1 A5 禁切点 —— 有效，但影响面只有个位数

**5 分钟区间 A/B**（600–900s，35 段，两端用同一批段文本重切、都不加 padding）：

| 指标 | A5 开 | A5 关 |
|---|---|---|
| 字幕条数 | 60 | 60 |
| 段内接缝 | 25 | 25 |
| **切在禁切位置** | **0** | **1** |
| CER | 19.28% | 19.28% |
| cps 最大 / p95 / 中位 | 8.4 / 7.3 / 5.1 | 8.4 / 7.3 / 5.1 |

唯一的差异就是它该管的那一处：

```
A5 关：…子供じみた場所にいるよ | うな気がして、     ← 「いるような」被劈成「いるよ」+「うな」
A5 开：…子供じみた場所に | いるような気がして、     ← 正确
```

**全片反事实**：交付字幕 145 处段内接缝，**禁切 0 处**；把同一批段文本用「关闭 A5」重切，会出现 **3 处**断词。

**判定：目标 100% 达成（断词 0），但量级是个位数，对 CER 没有影响。** 它是护栏，不是提分项——这一点和文档里的定位一致。

### 4.2 A6 对齐四桶 —— 桶守恒成立，但「插值率定位识别错」不成立

真实 Qwen 跑 3 个区间（默认参数，16s 上限）：

| 区间 | 段 | 对齐 | noop | 退化 | 空 | 四桶和 | 插值 | 截断 | 复读 | 区间 CER |
|---|---|---|---|---|---|---|---|---|---|---|
| 290–330s（新闻播报） | 3 | 3 | 0 | 0 | 0 | **3** ✅ | 12/84（14.0%） | 0 | 0 | 19.8% |
| 95–110s（复读段） | 1 | 1 | 0 | 0 | 0 | **1** ✅ | 6/10（60.0%） | 0 | 0 | **0.0%** |
| 42:00–42:40（歌曲） | 6 | 5 | 0 | 0 | 1 | **6** ✅ | 8/105（7.6%） | 0 | 0 | 24.8% |

四桶 `aligned + noop + degraded + empty == segments` 在三组里都成立——**报告不再对不上账**，这是 A6 的真实价值。

但文档里那句「插值率是识别错误的定位器」被实测否掉了：

| 段 | 插值率 | CER |
|---|---|---|
| 05:06.330 | 15%（最高） | **5.9%**（几乎全对） |
| 05:13.880 | 15% | 27.1% |
| 42:25.830 | 6%（最低） | **25.7%**（错得多） |

插值率最高的那段反而是全对的那段，最低的那段 CER 25.7%。**7 段样本里两者没有相关，甚至反向。** 更可能的解释是：插值率标的是「文本字数与这段声学时长不匹配」（VAD 切短了、语速极快、或 CTC 头在这段退化），而不是「识别错了」。

**判定：作为「账目可核对」的观测是有效的；作为「错误定位器」不成立，别按它去挑段重跑。**

### 4.3 P4 撞上限分类 —— 本片没有样本

3 个区间共 7 段，`truncated=0`、`capped_repeat=0`——**没有任何一段吃满 token 上限**。P4 改的是「撞上限时要不要重跑」的判据（字/token 密度 0.5 区分真截断与复读），本片连撞都没撞到，因此无法从真实素材上验证，只有单测覆盖。

**判定：未触发，维持现状。** 它属于「防御性改动」，只在复读/超长段上兑现。

### 4.4 P6 / P7 性能

| 项 | 改前 | 改后 | 倍数 |
|---|---|---|---|
| P6 波形（进程重启后首次进核对台） | 186 ms | **42 ms**（磁盘缓存） | 4.4× |
| P6 波形（同一进程内） | — | 0.117 ms | — |
| P7 禁切表（60 条长句） | 24 ms | **0.6 ms** | 42× |

P7 的 42 倍听着漂亮，但绝对值是 0.6ms——**在一次 194 秒的转写里是 0.0003%**。它的真实价值是消除平方项、为共用禁则铺路，不是省时间。

## 5. BGM / 歌曲段专题（42:00–44:20）

你指的那一段，实际上是**主题歌《Rain》**（参考字幕在此处是歌词），不是「台词 + 背景音乐」。这决定了它的难点：唱段的音素与说话差别很大，且和伴奏混在一起。

| 产物来源 | 该区间字幕条数 | 区间 CER | 备注 |
|---|---|---|---|
| **你交付的那份** | **1 条** | **99.72%** | 只在 43:33 出了一条 `…ジジャモ`（幻觉碎片） |
| 同代码重跑 #1 | **27 条** | 55.99% | 能听出歌词：「変わらずいる」「傷つくようなキミならもういらない」… |
| 同代码重跑 #2 | **27 条** | 55.99% | 与 #1 逐条完全一致 |
| 单独跑该区间（140s 切片） | 25 条 | 55.71% | — |
| 该区间 + `loudnorm=开` | 38 条（40:00–45:00） | — | 响度归一化不是原因 |
| 该区间 + `loudnorm=关` | 28 条（40:00–45:00） | — | — |

**这一段暴露的问题不是优化项，而是两件别的事**：

1. **VAD 只覆盖 63.4s / 140s（45%）**——阈值 0.45 时伴奏被当成「非语音」，唱段被切得七零八落；调到 0.28 可覆盖 94s。
2. **模型对唱段是「能听但听错」**：`レイディ、君は雨に` ← `Lady 君は雨に濡れて`、`としゃぶりでもかまわないと` ← `どしゃぶりでもかまわないと`。**没有出现大段幻觉**（整段插入只有 11 字），主要是漏字与听错。
3. **你交付的那份在这里几乎全丢（1 条 vs 27 条）**，且无法复现 → 见 §6。

## 6. 意外发现：交付字幕不可复现（417 vs 474）

这是本次测试里最需要你知道的一件事。

**可复现性检验**：同一份代码、同一组参数、同一份 16k 音频（md5 校验与缓存 wav 完全一致），全片连跑两次：

```
第一次：474 条，漏句 8 条，216.6s
第二次：474 条，漏句 8 条，202.9s
逐条比对：(start, end, text) 完全一致，差异 0 条
```

**也就是说当前代码是确定性的。** 但你交付的那份是 **417 条 / 漏句 2 条**，差异 57 条，且分布极不均匀：

| 区间 | 交付版 | 重跑 |
|---|---|---|
| 15–20min | 40 条 | 49 条 |
| 20–25min | 50 条 | 49 条 |
| **40–45min（歌曲）** | **10 条** | **61 条** |
| 其他区间 | 差 ≤3 条 | — |

一个具体例子（14:49 附近）：

```
交付：887.7 意外に不器用なんですね / 890.6 ごめんなさい。
重跑：887.1 意外に不器用なんですね / 889.0 何よ、ごめんなさい。   ← 多捞回一句「何よ」
```

**结论**：交付那次运行的状态与现在不同。为了缩小范围，我逐个排除了四个常见原因：

| 可能原因 | 实测 | 结论 |
|---|---|---|
| 响度档位搞反（`loudnorm` 开/关） | 同一区间 38 条 / 28 条 | ❌ 两档都远多于 10 条 |
| `max_segment_s` 不是 12 | 8 / 12 / 16 / 20s 各跑一遍，BGM 窗口都是 20 条 | ❌ 与上限无关 |
| VAD 阈值比报告的 0.45 更高 | 0.55 / 0.65 / 0.75 → BGM 窗口 16 / 14 / 13 条 | ❌ 阈值再高也到不了 1 条 |
| 代码版本不同（第二批改动） | `transcribe.py` 的第二批 diff 是**纯新增**（常量 + 禁切函数 + 兜底切分），不碰 VAD 与合并 | ❌ 不可能是代码导致 |

四个都排除后，最可能的是**那次运行的进程状态**（例如 7860 上跑的是改动前启动的旧进程——本项目以前踩过这个坑），或那次用的参数与你贴的报告不一致。**我无法复现它，也无法证明是哪一种。**

**建议**：以重跑结果为准（CER 25.08% vs 31.61%，差 6.5pt，几乎全部来自歌曲段），并检查那次运行前是否重启过 `app.py`。这份 417 条的字幕不建议作为质量基线继续用。

> 注：本报告 §2 的「交付版」数字是照你给的文件算的；§7 的归因分析用的是**可复现的重跑版**（474 条），因为它才是当前代码的真实输出。

## 7. 真正的损失在哪里（这决定下一步做什么）

用重跑版（474 条）做逐块归因，把每个参考块的错误分到三档：

| 归因 | 块数 | 占比 | 涉及字数 | 错/漏字数 | 占全部错字 |
|---|---|---|---|---|---|
| 基本正确（≥60%） | 350 | 72.6% | 4221 | 319 | 25.2% |
| 识别错（有字但错） | 51 | 10.6% | 387 | 268 | 21.2% |
| **VAD 没覆盖（根本没送去识别）** | **81** | **16.8%** | **707** | **677** | **53.6%** |
| VAD 有覆盖但没出字 | **0** | 0% | 0 | 0 | 0% |
| 合计 | 482 | — | 5315 | 1264 | 100% |

**三个可以直接读出来的结论**：

1. **一半以上的错字来自 VAD 召回不足**（677/1264）。这 81 个块模型根本没机会看到。典型样本：`新宿に到着です ご乗車ありがとうございました`（站内广播）、`危ないですから 黄色い線までお下がりください`、`鳴る神の`（短句）。
2. **A3 瞄准的那一档是 0 块**。所以「漏句清单为空」在这份素材上是**正确但无用**的信息——它保证的不是「没漏句」，只是「没有整段吐空」。
3. **「段内吃字」仍在，但证据强度弱于 VAD**：重跑版里仍能抓到实例——`910.5 早く来いよ` 被识别成 `ちゅうっ`，`918.5 ありがとう` 被并进 `お誕生日おめでとう、お母さん。あ…` 而消失。这类错误在归因里落在「识别错」档（268 字），不在 A3 能看见的「整段吐空」档。它多半来自 `merge_gap_s=0.3` 把短句并进相邻长句后，模型在长 chunk 里丢掉尾巴。

## 9. 建议的下一步（按 ROI 排序）

两批优化把「刀口」和「账目」都修好了，但**没有一项落在真正的损失上**。若要继续提分，优先级应该是：

1. **VAD 召回（可影响 54% 的错字）**
   阈值 0.45 对本站素材偏保守：全片语音 882s（32%），调到 0.28 是 985s。实测该段最缺的 15–25min 正好是轻声对话 + 雨声。建议先做「分段阈值」或「0.45 检出 + 0.28 复核」的双阈值，别全局降阈值（会把雨声一起放进来）。
2. **段内吃字（可影响约 21% 的错字）**
   证据：`910.5 早く来いよ` → `ちゅうっ`、`918.5 ありがとう` 被并进长句后消失。可试 `merge_gap_s` 0.3 → 0.15，或对「合并后 >8s 且内含 ≥2 个 VAD 段」的块做二次切分。这一项 A1 帮不上（它不是强制切分）。
3. **歌曲段单独策略**
   唱段用同一套 VAD + ASR 必然掉。要么标成「不转写」，要么上人声分离后再识别，别指望调参。
4. **A3 的告警加一道过滤**
   现在的 2 条记录都是 5% 分位响度的静音误判。加一个「段内峰值 < 阈值且参考无关」的过滤，或者干脆只在 `reason=retry-suspicious` 时告警，保住清单的信噪比。
5. **A1 / A6 / P4 / P7 维持现状**
   无收益也无伤害，不必再投入；A1 若要回退，`CUT_SNAP_S=0` 即恢复旧行为。
