```
core/

└── smoke.py           # 新增：9 段内核自检
```

**搬包时踩到的坑（已修，后续别再踩）**：原代码用 `Path(__file__).resolve().parent`
推算仓库根，模块一旦进了 `core/`，这个值就变成 `core/` 自己，`models/`、`outputs/`、
`presets.json` 会全部指向错误位置。现在统一走 `core/paths.py`：

```python
APP_ROOT = Path(__file__).resolve().parent.parent
MODELS_DIR  = _env_path("KIKUSUB_MODELS_DIR",  ROOT / "models")
OUTPUT_DIR  = _env_path("KIKUSUB_OUTPUT_DIR",  ROOT / "outputs")
PRESETS_PATH= _env_path("KIKUSUB_PRESETS_PATH",ROOT / "presets.json")
STATIC_DIR  = _env_path("KIKUSUB_STATIC_DIR",  ROOT / "static")
```

环境变量覆盖是给打包后用的：`.app` 内的 `Resources/python/` 是只读的，可写目录必须
挪到 `~/Library/Application Support/KikuSub/`。

### 1.4 环境侧发现（会持续影响后续阶段）

1. **venv 里没有 `pip`**，是 `uv` 管理的（`uv 0.9.24`）。装包一律用
   `uv pip install --python .venv/bin/python <pkg>`。已装 `pyinstaller 6.22.3`。
2. **PyInstaller 的 `--clean` 与「删除旧 dist 目录」都会触发宿主的批量删除确认**，
   在后台/非交互 shell 里会被直接拒绝。`build_probe.sh` 已改为自己先 `rm -rf` 目标目录，
   且不传 `--clean`。
3. **PyInstaller 的 COLLECT 阶段需要读取 `.venv` 里成千上万个文件**，必须在前台、
   允许授权提示的 shell 里跑；后台跑会卡在文件策略上。

### 2.2 关键设计决定（与规划一致 / 或对规划的具体化）

1. **导入是「传路径」而不是「传文件」**。桌面端 Electron 拿到的就是本地绝对路径，
   3 GB 的 MKV 没有任何理由复制一份走 HTTP。`POST /api/media` 收 `{"path": "..."}`，
   只做校验 + ffprobe 元数据探测，重复导入同一路径是幂等的（id = 路径哈希）。
2. **`/media/*` 用 `?token=` 而不是 Authorization 头**。`<video src>` 由浏览器内核
   直接发起请求，发不了自定义头，这是唯一可行的方案。`/api/*` 仍走 Bearer 头。
3. **波形按 `(id, bins)` 做进程内缓存**，配合 `lod` 档位。实测：命中内存 **1.7 ms**，
   满足规划 §5 指标 2「< 16 ms」。（首次调用依赖 `audio_cache` 的 wav 落盘缓存，
   本次实测 0.10 s 是因为这台机器上已有 815 MB 历史 wav 缓存；冷解码 3.3 GB MKV
   仍需分钟级，这一段在阶段 4 接「导入即后台压制」时一并解决。）
4. **`gr.State` → cookie + 内存 dict**，撤销栈上限 100 步，服务端仍是唯一真源。

### 2.4 已完成：异步任务与进度流（阶段 2 主体）

| 端点 | 说明 |
| --- | --- |
| `POST /api/jobs` | 建转写任务（引擎 / 切片 / 参数透传），返回快照 |
| `GET /api/jobs` / `{id}` | 查活动任务 / 单任务状态与结果 |
| `DELETE /api/jobs/{id}` | 取消（只发信号，槽位由 worker 释放） |
| `WS /ws/jobs/{id}?token=` | 进度流：`snapshot` → `progress` → `done`/`error`/`cancelled` |

**编排复用**：`server/jobs.py` 直接调 `core.pipeline.run_transcription`，与旧 Gradio
界面是同一份实现。`app.py` 的 `transcribe_media` 现在只剩 Gradio 那一层（并发占槽、
进度卡片、九元组 yield、客户端断开时发取消信号）。

**两个真实竞态**（都是测试先红、才发现的，值得记住）：

1. **任务比 WS 快**：前端先 `POST` 建任务、再开 WS，中间几十毫秒里短片可能已经跑完。
   此时只发快照，订阅者会永远等不到终态而挂死（表现为 pytest 卡住直到被杀）。
   → `subscribe()` 在任务已结束时，把历史里的最后一条终态事件一并补投。
2. **循环绑错**：订阅者所在的事件循环 ≠ 建任务那个请求的循环
   （`TestClient` 甚至每个请求一个循环），`call_soon_threadsafe` 打错循环就永远
   不唤醒，表现为「只收到快照，之后什么都没有」。
   → 逐订阅者记录 `(queue, loop)`，发布时用**等待方自己的**循环。

## 怎么跑（给自己做冒烟用）

```bash
cd repo
VENV=../.venv/bin/python

# 1) 旧界面（功能完整，行为就是验收过的那一版；改内核后先在这里验回归）
$VENV app.py                       # → http://127.0.0.1:7860

# 2) 新服务层 + 旧界面并存（回退通道）
$VENV -m server --port 0 --legacy  # stdout 首行给出 port/token
#    → http://127.0.0.1:<port>/legacy/   旧界面
#    → http://127.0.0.1:<port>/api/health  新 API

# 3) 只跑内核自检
$VENV -m core.smoke

# 4) 全量测试（注意必须带 --basetemp，否则宿主的临时目录限制会让 tmp_path 全炸）
$VENV -m pytest -q --basetemp=./.pytest-tmp
```

手搓 API 冒烟（拿到 token 后）：

```bash
B=http://127.0.0.1:<port>; H="Authorization: Bearer <token>"
curl -s -X POST $B/api/media -H "$H" -H 'Content-Type: application/json' \
     -d '{"path":"/绝对路径/xxx.mkv"}'
curl -s -X POST $B/api/jobs  -H "$H" -H 'Content-Type: application/json' \
     -d '{"media_id":"<id>","engine":"whisper","start":300,"end":315}'
curl -s $B/api/jobs/<job_id> -H "$H"
curl -s $B/api/report        -H "$H"
```

## 阶段 3 续 · 导入修复 + 参数/质检/虚拟列表

### 1. 「导入任何视频都失败」的根因

报错是 `Unexpected token 'I', "Internal S"... is not valid JSON`。链路上有三层问题叠加：

1. **真正的根因**：从访达启动的 `.app` 只继承 `PATH=/usr/bin:/bin:/usr/sbin:/sbin`，
   而 Homebrew 的 ffmpeg 在 `/opt/homebrew/bin`。`ffprobe` 调不起来 →
   `POST /api/media` 抛未捕获异常。
2. **错误被吞**：Starlette 对未捕获异常回纯文本 `Internal Server Error`，
   前端 `JSON.parse` 直接炸，用户看到的是解析错误而不是「找不到 ffmpeg」。
3. **前端无容错**：`req()` 假设响应一定是 JSON。

修法（四处）：
- `main.cjs` 给 sidecar 补 PATH（`/opt/homebrew/bin` 等）+ `KIKUSUB_FFMPEG_DIR` 覆盖，
  启动日志打印实际找到的 ffmpeg 路径；
- `media.py` 捕获 `FileNotFoundError` → `MediaError`，直接告诉用户怎么装；
- `app.py` 兜底 `exception_handler`，任何异常都回 `{detail: "Type: msg"}`；
- `api.ts` 容忍非 JSON 响应。

> 附带发现：调试中几次「最小环境复现失败」其实是**单实例锁**——旧进程没退，
> 第二个进程拿锁失败直接 `quit()`，日志只打了种子那一行。

### 2. 参数界面（用户问「两路引擎各自调参的界面在哪」）

## 阶段 6 · 打包版功能补齐（2026-11-10）

这一轮处理的是「`.app` 能双击打开，但干不了活」的问题。四个用户可见故障，
三个根因都在服务层/前端状态链路上，最后一个才是打包本身。

### 1. 「加载参数失败：Not Found」

**根因不是参数接口写错，而是打进 `.app` 的 sidecar 是旧的。**
`build/pack/dist/sidecar` 构建于 13:54，而 `GET /api/params` 是 14:56 才加进
`server/routes_jobs.py` 的——PyInstaller 把 `PYZ` 打进了可执行文件，改源码不会
自动生效。

- 重新执行 `tools/pack/build_sidecar.sh` + `tools/pack/build_app.sh` 后恢复；
- 顺手把 `/api/params` 加进鉴权回归的参数化列表，并新增
  `test_params_endpoint_exposes_groups_and_defaults` 守住「预设键必须能在规格表找到」。

### 2. 转写结果从未写回会话（比参数 404 更严重）

实测证据（源码服务、真实模型、3.3 GB MKV 的 300–315 s）：

```
POST /api/jobs → done，result.cues = 4
GET  /api/cues → {"cues": [], "count": 0}      ← 空
```

`JobManager._run_transcribe` 只把结果塞进 `job.result`，从来没有碰过
`Session`。旧 Gradio 界面是 `.then()` 里自己更新 `gr.State`，新服务层漏了这一步。
所以桌面端表现为「进度走到 100%，跳到核对台，一条字幕都没有」，质检队列也永远
是 idle（它按会话绑定的媒体读 `.qa.json`）。

修法：

| 位置 | 改动 |
| --- | --- |
| `server/routes_jobs.py` | 用 `get_session` 依赖取会话（原来只读 cookie，而桌面端走 `X-Kikusub-Session` 头）；建任务前就把 `session.media_id` 绑好 |
| `server/jobs.py` | `_run_transcribe` 成功后调 `_apply_cues()` 写回会话；快照里补 `applied` / `cue_count` / `added` |
| `server/sessions.py` | 会话加 `RLock`——worker 线程写、请求线程读，避免列表撕裂 |
| `core/pipeline.py` | `TranscribeRequest.write_audit`：局部重转不覆盖整片质检队列 |

三种合并语义（`apply` 字段）分别服务三个入口：

- `replace`：整片转写 → 覆盖核对台；
- `append`：转写页「区间 + 追加」→ 合并去重；
- `replace_range`：核对台「重转此句 / 转写选区」→ **只替换该区间**，其余原样保留。

### 3. 核对台重写：播放头、缩放、框选、单句转录

原来的核对屏只能整片显示波形、点一下跳转；没有缩放、没有框选、没有播放头拖动。
用户说的「播放头完全消失」还有一层原因：**MKV 没压好代理时 `<video>` 解不出来，
`readyState=0`，而 `tick()` 无条件用 `video.currentTime`（恒为 0）覆盖播放头**。
现在只在 `readyState >= 2` 且确实在播时才让视频驱动播放头；点波形、拖播放头、
质检定位都能独立移动。

新增/修正：

| 能力 | 实现 |
| --- | --- |
| 窗口化波形 | `GET /api/media/{id}/peaks?from=&to=&bins=`，只 seek+read 窗口内样本；按**整片峰值**归一化，放大不会「越放越响」 |
| 缩放 | 滚轮 / 触控板捏合（ctrl+wheel）/ 滑块 / ± 按钮 / 双击局部放大，最小 0.5 s 视窗 |
| 平移 | 双指横移、Shift+滚轮、⌥ 拖动；播放中手动缩放/平移自动关掉「跟随」 |
| 播放头 | 常驻竖线 + 时间旗标；视窗外时变成边缘箭头，点击回到播放头；拖播放头可搓碟 |
| 框选 | 拖出选区、两侧手柄可调；显示起止与时长；试听 / 聚焦 / 清除 |
| 一键聚焦 | 「聚焦」按钮按播放头位置放大；质检「定位」直接把波形缩放到该条区间 |
| 单句转录 | 每行悬停出现「试听 / 重转此句」，走 `replace_range`，只替换这一条 |
| 选区转录 | 选区栏「转写选区」→ 局部任务 → 结果只落该区间；「填入转写」把区间带到转写页 |
| 字幕叠加 | 同区间多行（中日双语）合并渲染，不再只显示一行 |

顺带修掉两个会直接毁掉界面的真 bug：

1. **`.sel` 类名冲突**：波形选区的 `.sel { position:absolute; top:17px }` 命中了
   表格的 `.row.sel`（选中行），于是第一、二行被绝对定位叠在一起。选中行改名为
   `.row-sel`。
2. **导入页 effect 自触发**：`ImportView` 的「最近打开」effect 读 `recents` 又写
   `recents`，Svelte 抛 `effect_update_depth_exceeded` → 白屏。读旧值改走 `untrack`。

### 4. 质检：改成逐项勾选

`QaPanel` 从「只读列表 + 几个按钮」改成核对清单：

- 每条左侧复选框：勾上 = 已核对（`mark done`），再点放回；
- 待核 / 全部 / 已处理三档筛选 + 进度条 + 「下一个」；

- 「补录」直接对该条区间做局部转写，**成功后才**标记 `filled`；失败不标记；
- 空态显示本次检查了多少切片/字幕，以及三类检查各自的「已检查 / 引擎不启用」。

### 5. 报告页

- 每个质检段落可展开逐条明细（时间码、规则、峰值、文本），点时间码回核对台并聚焦；

- 报告内核与旧 Gradio 共用，文案里带 ✅🔍 emoji；桌面端渲染前统一剥掉，保持零 emoji。

### 6. 字幕导入

`POST /api/cues/import {path}` 读本地 SRT/VTT 整表替换核对基线（压撤回栈）。
渲染进程按后缀分流：`.srt/.vtt` 走字幕导入，其余走媒体导入——之前双击 `.srt`
会被当成视频导入然后报「不支持的文件格式」。

同时修掉主进程「打开…」的双重导入：`pickMedia()` 既返回路径又广播
`file:opened`，渲染进程自己调 IPC 时会导入两遍。现在只有菜单路径广播事件。

### 7. 打包侧的隐藏雷：冻结后 multiprocessing

打包版真跑转写时，stderr 里出现：

```
python -m server: error: unrecognized arguments: -B -S -I -c from multiprocessing.resource_tracker import main;main(11)
```

torch 的分布式模块会 spawn `multiprocessing.resource_tracker`。冻结成可执行文件后，
这个「子进程」就是重新执行 sidecar 本身，参数却是 Python 解释器的 `-B -S -I -c ...`。
`tools/pack/sidecar_entry.py` 之前没有调 `multiprocessing.freeze_support()`，于是子进程
直接撞进 `server/__main__.py` 的 argparse。这一次主流程没有立刻失败，但属于定时炸弹。

修法：在入口**任何重依赖导入之前**调用 `multiprocessing.freeze_support()`；
PyInstaller 的 `pyi_rth_multiprocessing` 会接管并执行 tracker 代码后退出。

另外给主进程加了 `KIKUSUB_DATA_DIR` 覆盖（默认仍是 `~/Library/Application Support/KikuSub`），
无头验证和「把数据放到别的盘」都用得上。

## 阶段 7 · 质检队列、日志、波形与设置（2026-11-10 晚）

### 1. 「报告有 4 条待核，质检面板 0 条」

**根因是我们在上一轮修局部重转时矫枉过正**：`write_audit` 被设成
「只有整片转写才写」，于是转写页里带时间区间的任务（用户常说的「转一个片段」）
不落 `.qa.json`。报告读的是任务内存里的 `report.quality`，质检面板读的是磁盘队列，
两边自然对不上。

修法：`write_audit = apply != "replace_range"`。

| 入口 | apply | 是否写队列 |
| --- | --- | --- |
| 转写页 · 整片 | replace | ✅ |
| 转写页 · 区间 | append | ✅（用户看到的报告就是这次片段） |
| 核对台 · 重转此句 / 转写选区 | replace_range | ❌（保留整片队列，避免冲掉核对进度） |

另外 QA 面板加了兜底提示：如果 `phase=idle` 但当前报告有 `missed+dropped+suspect > 0`，
会直接说「队列为空，但报告里有 N 处待核」，并指向设置页的日志，而不是显示「0 条」。

### 2. 日志：之前根本没有落盘

排查时发现一个更基础的问题：**服务层从未调用 `setup_logging()`**。
旧 Gradio 入口 `app.py` 里有，新的 `server/__main__.py` 漏了，所以
`~/Library/Application Support/KikuSub/outputs/logs/` 一直是空目录，只有终端 stderr。
用户关掉窗口后什么都不剩。

这一轮补成完整链路：

| 日志 | 内容 | 位置 |
| --- | --- | --- |
| `kikusub.log` | sidecar：启动横幅（版本/打包/Python/目录/ffmpeg）、每个 API 请求（方法/路径/状态/耗时/请求 id/会话 id）、转写参数与完成、质检队列读写、异常堆栈 | `outputs/logs/kikusub.log`，5 MB × 3 轮转 |
| `main.log` | Electron 主进程：数据/模型目录、ffmpeg 查找、sidecar 启动/握手/退出、渲染进程 error/warning、未捕获异常 | `outputs/logs/main.log` |
| 渲染端事件 | `POST /api/log`：API 失败（带 `X-Request-Id`）、未捕获异常、视频解码失败、导入/转写/质检/导出/设置等关键动作 | 合并进 `kikusub.log`（logger=`kikusub.renderer`） |

界面侧：

- 左下「设置」现在能打开，包含「日志与诊断」区；
- 一键 **复制诊断信息**（版本、目录、ffmpeg、设置、引擎状态、最近日志、最近 ERROR/WARNING）
  和 **复制最近日志**，适合直接发给我；
- 菜单「帮助 → 打开日志目录 / 打开数据目录」在打包后指向 Application Support，
  不再错误地指向只读的 `.app` 内部；
- 诊断接口：`GET /api/diagnostics`、`GET /api/diagnostics/log?lines=N`、`POST /api/log`。

> 日志会包含本机文件路径与转写片段文本；**token / Authorization 头在格式化出口统一脱敏**
> （uvicorn 的 WebSocket 访问日志会带 `?token=`，已由 `_RedactingFormatter` 替换成 `token=***`）。

### 3. 波形：纵向高度 + 采样密度

| 改动 | 数值 |
| --- | --- |
| 默认高度 | 96 px → **148 px**，底部把手可拖到 110–300 px（记在 localStorage） |
| 采样点数 | 每像素 1 点 → **每像素 3 点**（512–12000 点/窗口），放大到 1 秒视窗仍有足够包络 |
| 绘制方式 | 一个包络点画一根柱子 → **逐像素合取最大包络**，任意缩放下都是连续波形，不再出现可数的柱形 |
| 显示增益 | 全局峰值归一化后加 `amp^0.72 × 1.08` 的轻 gamma，弱对白抬起来、满幅配乐仍封顶 |
| 刻度 | 修掉 `0.1s` 档出现 `1:39.10` 的两位小数 |

服务端对应的窗口接口 `GET /api/media/{id}/peaks?from=&to=&bins=` 一次只 seek + read
窗口内样本，所以 12000 点也不会把整片重新解码。

### 4. 设置页与引擎配置

新增 `core/engines.py`（**无 torch 依赖**）作为引擎注册表，`core/settings.py` 落盘应用设置。

引擎卡片由注册表驱动，显示：名称、用途、语种、预计/实际占用、建议内存、HF 仓库、
模型目录、安装状态、启用开关、下载/校验按钮、下载进度（磁盘增长估算，单调）。
已安装的卡片提供「校验 / 补齐」——权重缺文件时会自动补下（`ensure_model` 幂等）。

| 接口 | 说明 |
| --- | --- |
| `GET /api/settings` | 设置 + 引擎状态（含目录大小）+ 运行环境 + 目录 |
| `PATCH /api/settings` | `enabled_engines` / `auto_proxy`，原子写 `settings.json` |
| `GET /api/engines` | 引擎列表 |
| `POST /api/engines/{key}/download` | 起一个 `kind=download` 任务，复用单槽与 WS 进度 |

行为：

- 顶部工具栏只列 **已启用** 的引擎；全停用时显示「没有启用的引擎」并直达设置；
- 停用当前引擎会自动切到第一个可用引擎；
- 转写页的引擎分段同样只列启用的；停用引擎的转写请求会被前端拦下；
- 下载与转写共用单槽（都吃网络/磁盘/CPU），冲突时提示「已有任务在运行」。

**以后新增引擎**只需要：

1. 在 `core/engines.py` 的 `ENGINES` 加一条 `EngineSpec`（语种、体积、repo、必需文件）；
2. 在 `core/pipeline.py` 注册实际推理对象（`resolve_engine` / `_ENGINE_OBJECTS`）；
3. 在该引擎对象上提供 `ensure_model(progress_cb)`。

设置页、工具栏过滤、下载按钮、安装检测都会自动出现，不用改前端。

## 阶段 4 续 · 主题 / 快捷键 / 日志 / 退出清理 / 首次启动（2026-11-10）

### 1. 暗色主题下侧栏（红绿灯列）配色

窗口是 `hiddenInset + vibrancy:'sidebar'`，原生毛玻璃的明暗由 macOS 系统外观决定，
只切 `<html data-theme>` 会让深色主题下最左侧一列透出系统浅色。修复分两层：

- 渲染层切主题时通过 preload `setTheme()` 通知主进程设置 `nativeTheme.themeSource`；
- 深色 `--bg-sidebar` 从 `rgba(38,38,40,.5)` 提到 `rgba(30,30,32,.92)`，压住可能的浅色底；
- `main.ts` 在 Svelte 挂载前先应用 localStorage 里的主题，消除冷启动闪白。

### 2. ⌘, 打开设置

菜单保留 `设置…` accelerator；渲染层 `onKey` 在输入框 early-return 之前再兜一层
（输入框聚焦时菜单快捷键可能被输入法吃掉）。`Ctrl+,` 同样可用。

### 3. 日志清理

- `core.logging_setup.prune_logs()`：只删 `*.log.N` 轮转备份，活动日志永不删；
  策略 14 天 / 整个日志目录 64 MB。
- `setup_logging()` 启动时执行；sidecar 每 6 小时后台执行；Electron 主进程启动时
  用 `desktop/main/files.cjs` 的 `pruneLogs()` 执行同一策略。
- 设置页「清理旧日志」→ `POST /api/diagnostics/log/clean`，与自动策略同源。

### 4. 退出前的碎片字幕 / 视频代理清理

- 主进程在 `before-quit` 与窗口 `close` 时扫描 `outputs/` 顶层区间碎 SRT
  （`00m40s-00m52s` / `from_` / `to_`，含 `.qwen` / `.part_cancelled`）与
  `outputs/web_proxies/*.mp4`，经 `quit:prompt` 交给渲染进程逐个勾选。
- 默认全不勾选；勾选保留，未勾选删除。没有窗口可询问时保留文件，绝不无人确认就删。
- 删除前先停 sidecar 并等它退出，避免和正在写的代理/字幕抢文件；确认期间
  `quitConfirming` 阻断重复的 before-quit / close。
- 实测：默认 2 个未勾选 → 确认后文件删除、sidecar 正常退出；取消则文件与窗口都保留。

### 5. 首次启动选择模型目录

- 主进程判定首次启动：无 `preferences.json`、无 `KIKUSUB_MODELS_DIR`、模型目录里没有权重。
  旧用户已有模型则跳过。
- 首次向导（`FirstRun.svelte`）列出默认目录、可浏览其他位置、目录不可写时原地报错；
  完成前不启动 sidecar。
- 偏好写入 `preferences.json`（`modelsDir / setupCompleted / theme`），之后 sidecar 启动时
  显式带 `KIKUSUB_MODELS_DIR`，模型下载与安装检测都落在该目录。
- 设置页可随时「更改…」模型目录；保存后自动重启 sidecar，渲染进程修复为可在
  `sidecar:down → sidecar:ready` 后重新握手。内核重启会清空进程内会话，界面同步回到导入，
  改目录前会提示先导出 SRT。
- 打包版实测（`KIKUSUB_DATA_DIR=/tmp/fresh` + `KIKUSUB_FORCE_FIRST_RUN=1`）：
  向导 → 选目录 → sidecar 起来（`frozen=True`）→ 自动创建
  `models/ outputs/logs outputs/web_proxies presets.json preferences.json`，
  引擎显示「未下载」，符合真实首次安装。
