**搬包时踩到的坑（已修，后续别再踩）**：原代码用 `Path(__file__).resolve().parent`
推算仓库根，模块一旦进了 `core/`，这个值就变成 `core/` 自己，`models/`、`outputs/`、
`presets.json` 会全部指向错误位置。现在统一走 `core/paths.py`：

```python
APP_ROOT = Path(__file__).resolve().parent.parent
MODELS_DIR  = _env_path("KIKUSUB_MODELS_DIR",  ROOT / "models")
OUTPUT_DIR  = _env_path("KIKUSUB_OUTPUT_DIR",  ROOT / "outputs")
PRESETS_PATH= _env_path("KIKUSUB_PRESETS_PATH",ROOT / "presets.json")
STATIC_DIR  = _env_path("KIKUSUB_STATIC_DIR",  ROOT / "static")
```

环境变量覆盖是给打包后用的：`.app` 内的 `Resources/python/` 是只读的，可写目录必须
挪到 `~/Library/Application Support/KikuSub/`。

### 1.4 环境侧发现（会持续影响后续阶段）

1. **venv 里没有 `pip`**，是 `uv` 管理的（`uv 0.9.24`）。装包一律用
   `uv pip install --python .venv/bin/python <pkg>`。已装 `pyinstaller 6.22.3`。
2. **PyInstaller 的 `--clean` 与「删除旧 dist 目录」都会触发宿主的批量删除确认**，
   在后台/非交互 shell 里会被直接拒绝。`build_probe.sh` 已改为自己先 `rm -rf` 目标目录，
   且不传 `--clean`。
3. **PyInstaller 的 COLLECT 阶段需要读取 `.venv` 里成千上万个文件**，必须在前台、
   允许授权提示的 shell 里跑；后台跑会卡在文件策略上。

### 2.2 关键设计决定（与规划一致 / 或对规划的具体化）

1. **导入是「传路径」而不是「传文件」**。桌面端 Electron 拿到的就是本地绝对路径，
   3 GB 的 MKV 没有任何理由复制一份走 HTTP。`POST /api/media` 收 `{"path": "..."}`，
   只做校验 + ffprobe 元数据探测，重复导入同一路径是幂等的（id = 路径哈希）。
2. **`/media/*` 用 `?token=` 而不是 Authorization 头**。`<video src>` 由浏览器内核
   直接发起请求，发不了自定义头，这是唯一可行的方案。`/api/*` 仍走 Bearer 头。
3. **波形按 `(id, bins)` 做进程内缓存**，配合 `lod` 档位。实测：命中内存 **1.7 ms**，
   满足规划 §5 指标 2「< 16 ms」。（首次调用依赖 `audio_cache` 的 wav 落盘缓存，
   本次实测 0.10 s 是因为这台机器上已有 815 MB 历史 wav 缓存；冷解码 3.3 GB MKV
   仍需分钟级，这一段在阶段 4 接「导入即后台压制」时一并解决。）
4. **`gr.State` → cookie + 内存 dict**，撤销栈上限 100 步，服务端仍是唯一真源。

### 2.4 已完成：异步任务与进度流（阶段 2 主体）

| 端点 | 说明 |
| --- | --- |
| `POST /api/jobs` | 建转写任务（引擎 / 切片 / 参数透传），返回快照 |
| `GET /api/jobs` / `{id}` | 查活动任务 / 单任务状态与结果 |
| `DELETE /api/jobs/{id}` | 取消（只发信号，槽位由 worker 释放） |
| `WS /ws/jobs/{id}?token=` | 进度流：`snapshot` → `progress` → `done`/`error`/`cancelled` |

**编排复用**：`server/jobs.py` 直接调 `core.pipeline.run_transcription`，与旧 Gradio
界面是同一份实现。`app.py` 的 `transcribe_media` 现在只剩 Gradio 那一层（并发占槽、
进度卡片、九元组 yield、客户端断开时发取消信号）。

**两个真实竞态**（都是测试先红、才发现的，值得记住）：

1. **任务比 WS 快**：前端先 `POST` 建任务、再开 WS，中间几十毫秒里短片可能已经跑完。
   此时只发快照，订阅者会永远等不到终态而挂死（表现为 pytest 卡住直到被杀）。
   → `subscribe()` 在任务已结束时，把历史里的最后一条终态事件一并补投。
2. **循环绑错**：订阅者所在的事件循环 ≠ 建任务那个请求的循环
   （`TestClient` 甚至每个请求一个循环），`call_soon_threadsafe` 打错循环就永远
   不唤醒，表现为「只收到快照，之后什么都没有」。
   → 逐订阅者记录 `(queue, loop)`，发布时用**等待方自己的**循环。

## 怎么跑（给自己做冒烟用）

```bash
cd repo
VENV=../.venv/bin/python

# 1) 旧界面（功能完整，行为就是验收过的那一版；改内核后先在这里验回归）
$VENV app.py                       # → http://127.0.0.1:7860

# 2) 新服务层 + 旧界面并存（回退通道）
$VENV -m server --port 0 --legacy  # stdout 首行给出 port/token
#    → http://127.0.0.1:<port>/legacy/   旧界面
#    → http://127.0.0.1:<port>/api/health  新 API

# 3) 只跑内核自检
$VENV -m core.smoke

# 4) 全量测试（注意必须带 --basetemp，否则宿主的临时目录限制会让 tmp_path 全炸）
$VENV -m pytest -q --basetemp=./.pytest-tmp
```

手搓 API 冒烟（拿到 token 后）：

```bash
B=http://127.0.0.1:<port>; H="Authorization: Bearer <token>"
curl -s -X POST $B/api/media -H "$H" -H 'Content-Type: application/json' \
     -d '{"path":"/绝对路径/xxx.mkv"}'
curl -s -X POST $B/api/jobs  -H "$H" -H 'Content-Type: application/json' \
     -d '{"media_id":"<id>","engine":"whisper","start":300,"end":315}'
curl -s $B/api/jobs/<job_id> -H "$H"
curl -s $B/api/report        -H "$H"
```

### 需要你确认的 8 个设计决定

1. **布局**：侧栏 224 + 工具栏 44 + 正文 + 检查器 320 + 状态栏 26。
   侧栏通顶（红绿灯压在侧栏上），走 Finder / 备忘录那种 hiddenInset 观感。
2. **检查器只属于「核对」屏**。导入 / 转写 / 报告是文档式全宽——
   这是刻意的取舍：那三屏不需要「当前条目」这种上下文。
3. **工具栏只显示文件身份**（文件名 + 当前状态），页面标题放在正文里。
   之前试过两处都写标题，重复得很明显。
4. **波形用中性灰**，彩色只留给「选区」和「播放头」。
   这是 Logic / Final Cut 的惯例，也让「哪些是可交互的」一眼可辨。
5. **零 emoji，全套内联 SVG 图标**（模拟 SF Symbols 的线条风格）。
   旧界面满屏 🎬📁🚀，是最重的一股 Web 味。
6. **圆角 6 / 10 / 12**（控件 / 卡片 / 面板），1 px hairline，不用阴影堆叠。
7. **正文 13 px / 行高 1.38**，时间码用等宽字体 + `tabular-nums`。
8. **主色跟随系统 accent**（当前 #007aff），全站唯一彩色强调。

### 明确没覆盖（避免误判成遗漏）

- 质检浮标**展开后**的面板（只画了右下角入口）
- 设置页、参数预设管理
- 拖拽悬停态、空态、错误态
- 虚拟列表（1000 条字幕）、`content-visibility` 等阶段 4 的丝滑工程
- 窗口全屏 / 分屏 / Stage Manager
