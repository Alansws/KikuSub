## 阶段 1 · 抽 `core/` 包 + 打包预验证 ✅

### 1.1 抽包结果

七个模块用 `git mv` 搬进 `core/`，**算法逻辑零改动**，仅改导入方式：

```
core/
├── __init__.py        # 声明边界：禁止 import gradio / fastapi
├── paths.py           # 新增：运行期路径中枢
├── procutil.py        # 无内部依赖
├── jobs.py            # 无内部依赖
├── presets.py         # 无内部依赖
├── logging_setup.py   # 无内部依赖
├── audio_cache.py     # → .paths
├── transcribe.py      # → .audio_cache / .paths / .procutil
├── qwen_ctc.py        # → .procutil / .transcribe
└── smoke.py           # 新增：9 段内核自检
```

**搬包时踩到的坑（已修，后续别再踩）**：原代码用 `Path(__file__).resolve().parent`
推算仓库根，模块一旦进了 `core/`，这个值就变成 `core/` 自己，`models/`、`outputs/`、
`presets.json` 会全部指向错误位置。现在统一走 `core/paths.py`：

```python
APP_ROOT = Path(__file__).resolve().parent.parent
MODELS_DIR  = _env_path("KIKUSUB_MODELS_DIR",  ROOT / "models")
OUTPUT_DIR  = _env_path("KIKUSUB_OUTPUT_DIR",  ROOT / "outputs")
PRESETS_PATH= _env_path("KIKUSUB_PRESETS_PATH",ROOT / "presets.json")
STATIC_DIR  = _env_path("KIKUSUB_STATIC_DIR",  ROOT / "static")
```

环境变量覆盖是给打包后用的：`.app` 内的 `Resources/python/` 是只读的，可写目录必须
挪到 `~/Library/Application Support/KikuSub/`。

### 1.3 打包预验证（关键路径闸门）✅ 通过

（含 gradio 全套）都算进去了，而阶段 7 会删掉 Gradio。模型 6.6 GB 仍然外置、首启下载。

### 1.4 环境侧发现（会持续影响后续阶段）

1. **venv 里没有 `pip`**，是 `uv` 管理的（`uv 0.9.24`）。装包一律用
   `uv pip install --python .venv/bin/python <pkg>`。已装 `pyinstaller 6.22.3`。
2. **PyInstaller 的 `--clean` 与「删除旧 dist 目录」都会触发宿主的批量删除确认**，
   在后台/非交互 shell 里会被直接拒绝。`build_probe.sh` 已改为自己先 `rm -rf` 目标目录，
   且不传 `--clean`。
3. **PyInstaller 的 COLLECT 阶段需要读取 `.venv` 里成千上万个文件**，必须在前台、
   允许授权提示的 shell 里跑；后台跑会卡在文件策略上。
