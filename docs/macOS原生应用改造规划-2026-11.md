## 0. 先纠正一个前提

"内核跑通了，后端应该没问题" —— **内核没问题，但"后端"目前并不存在**。

| 层 | 现状 | 改造结论 |
| --- | --- | --- |
| 算法内核 `transcribe.py` / `qwen_ctc.py` / `audio_cache.py` / `jobs.py` / `procutil.py` / `presets.py` | 纯 Python，无 UI 依赖 | ✅ **零改动复用**，风险≈0 |
| `app.py` 123 个函数 | 其中 **29% 的行（1587 行）在拼 HTML 字符串**；41 个 Gradio 事件处理函数；4 个 `gr.State` | ⚠️ 需重写，是主要工作量 |
| HTTP 接口 | **不存在**。所有调用走 Gradio 私有事件协议（`fn_index` + SSE） | ❌ 必须新建 |
| 前端 `reviewer.js` 1125 行 / `qa_panel.js` 775 行 | 纯原生 DOM，自建节点，只通过隐藏 Textbox 与 Gradio 通信 | ✅ **可复用 ~90%** |
| `theme.css` 60KB | 设计变量 + 组件样式 | ✅ 作为设计 Token 基线 |
| 数据契约 `review_payload` / `qa_payload` | 已是 JSON 字符串 | ✅ **API schema 已现成**，直接升级为 OpenAPI |

**一句话**：算法层是资产，`app.py` 是负债，`static/` 是半个资产。改造的本质是**把 `app.py` 的 UI 层剥离出来重建**，算法一行不动。

体积现实（必须提前接受）：`models/` 6.6 GB + `.venv/` 1.0 GB。打包后 `.app` 约 **1.8–2.5 GB**，模型不内置、首启下载。这不是缺陷，是本地推理应用的常态（对比：LM Studio ≈ 2 GB）。

### 为什么是 Electron 而不是 Tauri

不是"Electron 更 Mac"，而是**这个应用的技术形状更适合 Chromium**：

1. **视频与 canvas 是核心**。Chromium 的 `requestVideoFrameCallback`、`OffscreenCanvas`、WebCodecs、WebGL 行为一致且性能稳定；WKWebView 在 `backdrop-filter` 与高 DPI canvas 重绘上明显更慢，且媒体行为随系统版本漂移。
2. **HEVC 解码**。Chromium 在 macOS 上可走 VideoToolbox 硬解 HEVC，WKWebView 的容器/编码支持更窄。
3. **包体劣势可忽略**。Electron 多 150 MB，而 Python sidecar 本身就是 2 GB；内存多 200 MB，而 torch 推理本身就占几 GB。
4. **不需要 Rust 工具链**（当前环境未安装），迭代循环更短。

真正决定"像不像 Mac"的是**设计规范与动效曲线**，不是运行时。VS Code / Linear / Figma / Discord 都是 Electron。

> 若你坚持 Tauri：架构完全一致，只需把外壳换掉。选择条件：内存敏感、要求 15 MB 级外壳、且愿意处理 WKWebView 的媒体差异。

## 2. 目标架构

```text
KikuSub.app  (Electron)
├─ main (Node)
│   ├─ 窗口：hiddenInset 标题栏 / vibrancy / 单实例 / 全屏 / 分屏
│   ├─ 菜单：App File Edit View Playback Window Help（⌘Z 必须真的接到前端栈）
│   ├─ 文件关联：.mkv .mp4 .srt .vtt 双击打开、Dock 拖放、最近打开
│   └─ sidecar 生命周期：启动即拉起、before-quit 必杀、崩溃自动重启
├─ preload：contextIsolation 下的受限 IPC（端口、token、文件对话框、最近列表）
└─ renderer (Svelte 5 + TS + Vite)
    ├─ 外壳：Sidebar / Unified Toolbar / SplitView / Inspector / StatusBar
    ├─ 视图：Import · Transcribe · Review · QA · Report · Settings
    └─ 命令式内核（原样复用）：reviewer.js（视频+波形+字幕表）、qa_panel.js（质检队列）
                     │ HTTP + WebSocket
                     ▼
    Python sidecar: uvicorn + FastAPI（127.0.0.1，随机端口 + token）
    ├─ core/   ← 原样搬入，加 __init__.py
    ├─ api/    ← 新写（见 §4）
    └─ /legacy ← Gradio 挂载，回退通道（阶段 7 后删除）
```

**为什么 sidecar 走 HTTP 而不是 stdio IPC**：视频 Range 请求、波形大数据块、进度流三件事天然属于 HTTP/WS；且开发期可直接开浏览器调试，迭代速度翻倍。

**端口与鉴权**：sidecar 以 `--port 0` 启动，OS 分配端口后写入 stdout 首行，main 读取后注入 renderer；同时下发一次性 token，所有请求校验 `Authorization`，防止本机其他进程调用。

## 4. API 面设计（把 41 个事件翻译成 ~24 个端点）

| 资源 | 端点 | 对应原逻辑 |
| --- | --- | --- |
| 媒体 | `POST /api/media`（上传/导入）<br>`GET /api/media/{id}`（元数据+时长）<br>`GET /media/{id}`（**必须支持 Range**） | `media.change` / `_media_duration_and_peaks` |
| 波形 | `GET /api/media/{id}/peaks?lod=` | `audio_cache.peaks` |
| 任务 | `POST /api/jobs`（转写/局部转写/代理压制）<br>`GET /api/jobs/{id}`<br>`DELETE /api/jobs/{id}`（取消）<br>`WS /ws/jobs/{id}`（进度流） | `transcribe_media` / `transcribe_selection_to_editor` / `manual_transcode_proxy_generator` |
| 字幕 | `GET/POST /api/cues`（批量）<br>`PATCH /api/cues/{i}`<br>`DELETE /api/cues/{i}`<br>`POST /api/cues/{i}/insert`<br>`POST /api/cues/undo` `redo`<br>`POST /api/cues/export` | 全部 `*_cue_btn` |
| 核对 | `POST /api/review/baseline`（设为基线）<br>`POST /api/review/append`（局部追加）<br>`POST /api/review/import`<br>`POST /api/review/export` | `latest_as_base_btn` 等 |
| 质检 | `GET /api/qa`<br>`POST /api/qa/action` | `qa_apply_action` |
| 预设 | `GET/POST/PUT/DELETE /api/presets` | `load/save/delete_preset` |
| 报告 | `GET /api/report`（**返回数据，不返回 HTML**） | `build_transcription_report` |

三个改造要点：

1. **`render_report_panel` / `_render_proxy_progress_card` / `_render_transcribe_progress_card` / `device_banner` 全部改为返回 JSON**，渲染交给前端组件。这是 `app.py` 里最需要重新设计的部分。
2. **`manual_transcode_proxy_generator`（1372 行）** 是 Gradio 流式生成器，每次 yield 一组组件 update。改造为 `POST /api/jobs` 创建 + `WS` 推送 `{percent, stage, text}`，前端卡片订阅。这条单独排 3 人日。
3. **`gr.State` → `session_id` cookie + 内存 dict**，沿用 `jobs.JobRegistry` 的单槽模型与 `CancelToken` 归属逻辑（这套并发加固已经是对的，别改）。

## 5. "丝滑"的 8 项可验收指标

不要用"感觉流畅"验收，用数字：

| # | 指标 | 现状 | 目标 | 手段 |
| --- | --- | --- | --- | --- |
| 1 | 播放时播放头跟随帧率 | `timeupdate` 约 4 Hz，肉眼抖动 | **≥ 60 fps** | `requestVideoFrameCallback` 取 `mediaTime` + rAF 插值 |
| 2 | 滚轮/捏合缩放波形首帧延迟 | 每次重算 peaks | **< 16 ms** | 服务端多档 LOD + 前端按 zoom 选档，缩放期只改 `transform` |
| 3 | 1000 条字幕滚动 | 全量 DOM | **不掉帧** | 虚拟列表（可视区 ±10 行） |
| 4 | ⌘Z 可见反馈 | 服务端往返 ~50–150 ms | **< 16 ms** | 前端 undo 栈乐观应用，后台同步，冲突以服务端为准重拉 |
| 5 | 冷启动到可交互 | 等 Python + 模型 | **< 2.5 s** | 启动即拉 sidecar，UI 先出骨架，模型懒加载 |
| 6 | 点击"开始转写"到进度出现 | 依赖 Gradio 往返 | **< 300 ms** | 乐观进度态 + WS |
| 7 | 拖入 3 GB MKV 到窗口 | — | **< 200 ms 有反馈** | 先渲染条目，再后台 ffprobe |
| 8 | 全屏 / 分屏 / Stage Manager | 浏览器全屏 | **系统原生** | Electron 原生窗口 API |

配套的渲染工程（第 2、3 条的技术底座）：

- **波形三层 canvas**：静态 peaks 层 / 选区层 / 光标层叠放。缩放平移时只重绘静态层，光标层只画一根线，彻底消灭全量重绘。
- **`content-visibility` + `contain: layout paint`** 隔离面板，避免 Inspector 更新触发整页 layout。
- **动效统一弹簧曲线** `cubic-bezier(0.32, 0.72, 0, 1)`，180–240 ms；列表项 120 ms；尊重 `prefers-reduced-motion`。
- **只动 `transform` / `opacity`**，禁止动 `width/top/left`。

## 6. 视觉规范（决定"像不像 Mac"）

| 项 | 现值（Web 味来源） | 改为 |
| --- | --- | --- |
| 图标 | 满屏 emoji（🎬📁🚀🔎） | **SF Symbols 全套替换** ← 收益/成本比最高的一条 |
| 主色 | 固定紫色渐变按钮 | 跟随系统 accent color（`AccentColor`），单一实色 |
| 圆角 | 16–20 px | 控件 6 / 卡片 10 / 面板 12 px |
| 边框 | 多层阴影 + 大圆角卡片 | 1 px `rgba(0,0,0,.08)` hairline，不用阴影堆叠 |
| 字体 | PingFang + 默认字号 | `-apple-system` 优先；正文 **13 px**，行高 1.38 |
| 布局 | 网页 header + 卡片流 | Sidebar + Unified Toolbar(44 px) + SplitView + Inspector + StatusBar |
| 控件 | Radio / Checkbox / Dropdown | Segmented Control / Switch / Popover |
| 侧栏 | 不透明灰 | 半透明 + `backdrop-filter: saturate(180%) blur(20px)` |
| 标题栏 | 浏览器标签 | `titleBarStyle: 'hiddenInset'`，红绿灯内嵌，标题栏可拖动 |

**建议先花 1–2 天做一张静态高保真稿**（就像 `review-assets/hallucination-report-preview.html` 那样），用真实数据、在浏览器里点一遍，方向确认后再动工。这一步能省掉大量返工。

## 7. 打包与分发

- **Python sidecar**：PyInstaller **onedir**（绝不用 onefile——每次启动解压 2 GB，冷启动 10 s+），产物放 `KikuSub.app/Contents/Resources/python/`。
- **模型外置**：首次运行下载到 `~/Library/Application Support/KikuSub/models`，带断点续传与镜像回退（沿用现有 `HF_ENDPOINT` 逻辑）。
- **签名**：仅本机自用 → `codesign --force --deep -s - KikuSub.app` 自签，首次打开 `右键 → 打开` 或 `xattr -dr com.apple.quarantine` 即可，**不需要 $99 开发者账号，不需要 notarytool**。
  > 若日后要分发，再补：Apple Developer 账号 + `notarytool` + hardened runtime，且必须加 entitlements `com.apple.security.cs.allow-jit` / `allow-unsigned-executable-memory` / `disable-library-validation`（torch 需要）。届时打包阶段会从 2 人日涨回 5 人日。
- **冷启动**：应用启动即预热 sidecar，不等到第一次点击；`ffmpeg` 用现有系统版本（当前 9.0.2 已在 PATH），找不到时降级提示并给安装指引。

## 8. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
| --- | --- | --- | --- |
| MKV/HEVC 在 Chromium 解不出 | 高 | 中 | 沿用 480p 代理（现已可用）并**改为导入即后台自动压制**，用户无感；必要时加 `--enable-features=PlatformHEVCDecoderSupport` |
| UI 重写工作量超预期 | 高 | 高 | 复用 `reviewer.js`/`qa_panel.js`；先做只读视图，再做编辑态 |
| torch 打包/签名失败 | 高 | 中 | onedir + 上述 entitlements；提前在阶段 1 就做一次打包验证，不要留到最后 |
| 前端 undo 栈与后端不一致 | 中 | 中 | 后端仍为唯一真源；前端栈只做乐观回显，服务端拒绝时整表重拉 |
| 端口冲突 / 进程泄漏 | 中 | 中 | 端口 0 + token + `before-quit` 强制 kill + 崩溃重启上限 3 次 |
| Gradio 依赖残留拖累安装包 | 低 | 低 | 阶段 7 彻底删除，可省 100 MB+ |
