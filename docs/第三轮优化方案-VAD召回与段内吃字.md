## 0. 一句话

上一轮证明了**「刀口」和「账目」都不是瓶颈**。这一轮只做两件事：

1. **让 VAD 别漏**——54% 的错字来自「这段根本没送去识别」；
2. **别把短句并掉**——21% 的错字是短句被并进长 chunk 后丢掉的。

### 1.2 三条已知尾巴（不改代码，但要写进文档/告警）

1. **A1 的吸附会累计位移**。每个切点前移 ≤0.4s，但下一个切点从新的 cursor 起算，实测 60s 窗口内 10 刀累计前移 2.4s，尾块被压到 2~3s。尾块过短时模型可能吐无关文本（实测 330s 窗口尾块出现 `この影響で、ブラックがスリップしたとみて` 这类幻觉）。
2. **A1 在「剩余长度恰为上限整数倍」时拒绝一切吸附**。`_cut_keeps_segment_count` 用上取整判定，60.0s / 6s 这种整倍数场景 `snapped=0`；实测踩到过，做 A1 相关实验时**窗口长度要避开整倍数**（用 60.4s）。
3. **A3 的漏句清单当前 0 精确率**。2 条记录都是 RMS 处于全片 VAD 段第 5/6 百分位的静音误判，参考字幕此处无台词。清单为空≠没漏句，它只覆盖「VAD 送了但模型吐空」这一档（本片为 0 块）。
4. **P1 改了波形的数据源**：从 1kHz 直读换成 16k 缓存，与旧包络的相关系数 0.873（不是逐字节相同）。视觉等价，但不要再声称「完全一致」。

1. **召回是最大的一块可动蛋糕**：从 0.45 降到 0.28，不达标字数 763→601，**理论 CER 上限改善 3.05pt**；降到 0.20 是 5.06pt；降到 0.08 是 6.59pt。

## 4. 优化方向（按 ROI 排序）

### D1 ★ 二次召回：对 VAD 没覆盖的空隙做补扫

**假设**：一次 VAD（0.45）为了保精度牺牲了召回；把「已覆盖区置零」后再用低阈值扫一遍空隙，可以用较低风险把 82 个不达标块里的多数捞回来。

**改法**（不改默认参数、不加 UI 滑块）：

```python
# 新模块 vad_recall.py（建议）
def gap_segments(audio, segs, sr, *, th=0.25, min_speech_ms=80,
                 min_silence_ms=150, pad_ms=120, min_gap_s=0.6):
    covered = np.zeros(len(audio), dtype=bool)
    for s, e in segs:
        covered[s:e] = True
    masked = np.where(covered, 0.0, audio).astype(np.float32)   # 时间轴不变，已覆盖区静音
    stamps = get_speech_timestamps(torch.from_numpy(masked), vad, sampling_rate=sr,
                                   threshold=th, min_speech_duration_ms=min_speech_ms,
                                   min_silence_duration_ms=min_silence_ms,
                                   speech_pad_ms=pad_ms, neg_threshold=vad_neg_threshold(th))
    out = [(s["start"], s["end"]) for s in stamps]
    return [(s, e) for s, e in out if (e - s) / sr >= min_gap_s]
```

召回后**必须过闸门**才采纳（否则音乐段会灌进幻觉）：

```python
def accept(text, dur, prev_text):
    if _is_blank(text): return False
    cps = len(re.sub(r"\s+", "", text)) / max(dur, 1e-6)
    if not (0.3 <= cps <= 12): return False        # 过密=复读，过疏=幻觉
    if _retry_suspicious(text, dur, prev_text): return False
    return True
```

**预期**：不达标块 82→60 左右，CER −1.5~−3.0pt。
**风险**：音乐/雨声段误检导致插入字数上涨。**这是本方向唯一的失败模式，必须用插入字数把关。**
**回退**：开关 `KIKUSUB_VAD_SECOND_PASS=0`（默认开），或把 `th` 调到 0.30。
**验收**：见 E2。

### D2 全局阈值 A/B（D1 的对照，也是最快的探路）

**假设**：也许根本不需要二次召回，直接把阈值降到 0.28~0.35 就够了。
**改法**：不改代码，只改参数跑全片（0.45 / 0.35 / 0.28 / 0.20 四档）。
**预期**：给出「阈值—CER—插入字数」的完整曲线，作为 D1 的基准线。如果 0.28 单档就能拿到 2.5pt 且插入不涨，D1 可以降级为「只补 0.28 也扫不到的尾巴」。
**风险**：低（纯参数）。
**验收**：见 E1。

### D3 合并策略：别把短句并掉

**假设**：`merge_gap_s=0.3` 把 `ありがとう`、`何よ`、`雨だ` 这类短句并进相邻长 chunk，模型在长 chunk 里丢掉尾巴。
**改法**：`merge_gap_s` 0.3 → 0.15（A/B 先验），或加一条「合并后 >8s 且内含 ≥2 个 VAD 段则二次切分」的规则。
**预期**：影响「识别错」那 268 字的一部分，CER −0.5~−1.5pt；顺带减少长 chunk。
**风险**：段数变多 → 耗时上涨（46 分钟从 210s 到约 240s）。
**验收**：见 E3。

### D4 歌曲/音乐段策略

**假设**：42:00–44:20 是主题歌，当前策略（同一套 VAD + ASR）CER 56%，但**跳过会更差**（426 字全丢 = 100%）。
**改法**：三选一，只做决策不做大改：
- (a) 维持现状（转写出错歌词，CER 56%）；
- (b) 低阈值 + 更短段（把唱段切细，让模型少猜）；
- (c) 人声分离（demucs）后再识别——工程量最大，建议单独立项。

**预期**：这一项**不以 CER 为唯一判据**，要看「可读性 vs 噪声」的产品取舍。
**验收**：见 E4。

### D5 A3 告警降噪（小项）

**改法**：漏句记录里加 `peak` / `rms` 字段；报告层只展示 `peak ≥ 阈值` 或 `reason=retry-suspicious` 的条目，其余留在 JSON。
**预期**：2 条噪声告警 → 0 条。
**验收**：见 E5。

### D6 单句超长（小项）

**现象**：重跑版有 **10 条 >4.3s**（最长 6.10s），因为 `split_text_into_cues` 在 `num_parts == 1` 时直接返回整段，忽略 `max_cue_dur`。
**改法**：`num_parts == 1` 且 `seg_dur > max_cue_dur` 时，按时间等分并用 `forbidden_cut_positions` 找合法切点。
**预期**：超长条 10→0，CER 不变。
**验收**：见 E6。

### E1 阈值扫描（40 分钟，含 4 次全片转写）

**目的**：拿到「阈值 → CER / 插入 / 漏块」曲线，决定 D1 要不要做。
**步骤**：写 `tools/eval/sweep_threshold.py`，对 0.45 / 0.35 / 0.28 / 0.20 各跑一次全片（复用 `eng._transcribe_array`，config 只改 `threshold`），落盘 SRT，然后逐个 `analyze.py`。
**看什么**：CER、插入字数、漏块数、VAD 不达标块数、耗时。
**判定**：
- 若某档 **CER 改善 ≥1.5pt 且插入 ≤90 字** → 该档直接可用，D1 降级为「补尾巴」；
- 若所有档 **插入 >120 字** → 说明低阈值在音乐段失控，D1 必须带闸门。
**预期耗时**：4×3.5min ≈ 15min 计算 + 分析。

### E2 二次召回 A/B（1.5 小时）

**目的**：验证 D1 能否用「低风险」拿到低阈值的收益。
**前置**：E1 已有 0.28 全片结果（作为上界对照）。
**步骤**：
1. 在 `transcribe.py::_transcribe_array` 的 `merge_vad_segments` 之后、逐段循环之前插入：

```python
if audio_cache_env_second_pass_enabled():
    extra = gap_segments(audio, segments, SAMPLE_RATE)      # 见 D1
    segments = sorted(segments + extra)
```

2. 逐段循环里对 `extra` 段加 `accept()` 闸门（`source="second_pass"`），被拒的记进 `last_missed_spans`（`reason="second-pass-rejected"`）。
3. 报告新增一行：`【二次召回】补扫 38 段，采纳 21 段，拒绝 17 段（复读 3 / 密度异常 9 / 空 5）`。
4. 跑全片，与 0.45 基线、0.28 全片结果三方对比。

**判定（三条同时满足才算通过）**：
- CER ≤ 23.0%（比 25.08% 改善 ≥2pt）；
- 插入字数 ≤ 90（当前 69，允许 +21）；
- 耗时 ≤ 280s（当前 210s）。
**回退**：`KIKUSUB_VAD_SECOND_PASS=0`。
**注意**：`gap_segments` 必须用**同一份 audio**（16k float32），且返回的样本索引要与 `merge_vad_segments` 同一坐标系（否则 `time_offset` 会错位——上一轮 A3 就是靠这一点保证时间轴正确的）。

### E3 合并间隔 A/B（40 分钟）

**步骤**：全片跑两遍，`merge_gap_s=0.3` vs `0.15`，其余不变；再用 `analyze.py` 对比。
**额外统计**：从参考块里挑出「≤5 字且被并掉」的样本（`ねえ`、`ありがとう`、`何よ`、`雨だ`），看这两遍各自捞回几条。
**判定**：CER 改善 ≥0.5pt 且耗时增幅 ≤15% 才算通过；若 CER 持平但短句召回 +5 条以上，也算通过（可读性）。
**风险**：段数上升 → 边界误差可能变差（当前起点中位 158ms），一并记录。

### E4 歌曲段三策略（40 分钟，只跑 40:00–45:00 这 5 分钟）

**步骤**：对同一段 300s 音频跑三种配置：
- (a) 现状：threshold 0.45 / max_segment 12；
- (b) 细切：threshold 0.30 / max_segment 6；
- (c) 人声分离后再跑（可选，需先装 demucs，没有就跳过并记录）。
**看什么**：区间 CER、条数、插入字数、cps 分布（歌词密，cps 会偏高）。
**判定**：**不以全局 CER 为判据**。给出三条各自的「条数 / CER / 插入」三元组，交给人判断「宁缺勿滥还是宁滥勿缺」。
**注意**：这段是歌，参考是歌词，**任何方案都不可能做到低 CER**，别把 56% 当成「还没调好」。

### E5 A3 告警降噪（20 分钟）

**步骤**：给 `last_missed_spans` 的每条记录加 `peak`、`rms`（取该段音频），报告层过滤 `peak < 0.02` 的条目。
**判定**：用参考字幕核对，展示出来的条目精确率 ≥50%，或（本片）展示 0 条。
**注意**：JSON 里保留全部记录，只在报告与核对台状态行里过滤——不要让信息消失，只是不要喊。

### E6 单句超长（20 分钟）

## 8. 坑（这一轮踩过的，别再踩）

1. **跑之前必须重启 `app.py`**。本项目发生过「改完代码没重启，跑的是旧进程」的事故：你交付的那份 417 条字幕，同代码重跑是 474 条，且**已排除**响度开关、`max_segment` 8/16/20s、VAD 阈值 0.45/0.55/0.65/0.75、代码版本（第二批改动纯新增、不碰 VAD 与合并）四个原因，仍无法复现。做实验一律用脚本直连引擎（`eng._transcribe_array`），不要点 UI。
2. **参考字幕 42:00 之后是歌词**。全片 CER 会被这一段带偏（交付版 99.7% vs 重跑 56%）。任何结论都要同时给「全片」和「去歌」两个数。
3. **`merge_vad_segments` 的 `audio` 参数决定吸附是否启用**。不传 `audio=` 就是旧行为，别拿它当对照还以为是新行为。
4. **A1 相关实验的窗口长度要避开 `max_segment_s` 的整数倍**，否则 `_cut_keeps_segment_count` 会拒绝一切吸附，你会得出「A1 没生效」的错误结论。
5. **macOS 的 BSD `grep` 不支持 `\|`**，`grep -n "a\|b"` 会静默返回空。查多模式用 Grep 工具或 `grep -E`。
6. **`outputs/` 在 `.gitignore` 里**。评测脚本不放 `tools/` 就等于没写。
7. **参考字幕含站内广播/电视新闻**（`新宿に到着です`、`気象庁は今朝`），这些块 VAD 天然难覆盖，追 100% 召回会把雨声一起放进来。
8. **MPS 是确定性的**（两次全片逐条一致），A/B 可信；但**不要跨设备比较**（CPU/MPS 结果会不同）。
